# Image Hunter

[English](README.en.md) | [中文](README.zh.md) | Русский
> **Страница проекта:** https://teliy.github.io/image-hunter/ · [Релизы](https://github.com/teliy/image-hunter/releases) · [Журнал изменений](CHANGELOG.md) · [Обсуждения](https://github.com/teliy/image-hunter/discussions)


Программа для Windows и Linux: **просмотр локальных изображений + поиск картинок в поисковиках + массовое сохранение по ссылкам** — всё в одном окне, на четырёх вкладках (четвёртая — «📜 Журнал»: хроника всей работы).

Написана на Python + PySide6 (Qt6): тяжёлые операции (рендеринг, сеть, декодирование картинок) выполняет нативный Qt, поэтому интерфейс быстрый и отзывчивый. Интерфейс доступен на **русском, английском и китайском** языках (выбор — в статус-баре, перевод применяется на лету).

> **⚡ Особый упор — быстрая работа в сети и с сетевыми дисками** (SMB/NAS, смонтированные папки, Windows-шары): папка читается одним обращением к диску, миниатюры строятся только для видимой части списка, готовые превью кэшируются на диске. Сетевая папка с тысячами фотографий открывается без «тормозов» — ни в программе, ни в сети. Подробности — в разделе [«Быстрая работа в сети и с сетевыми дисками»](#быстрая-работа-в-сети-и-с-сетевыми-дисками).

## Удаление водяных знаков — модуль Florence-2 + LaMa (v0.8.11)

Пожелание: «давай как модуль (который можно установить и удалить) добавим из github самый лучший удаляльщик watermark». Лучшее с GitHub связывается в один локальный конвейер из двух открытых инструментов — по образцу D-Ogi/WatermarkRemover-AI: **Florence-2** (microsoft, через transformers) задачей `<CAPTION_TO_PHRASE_GROUNDING>` с фразой «watermark» находит надписи водяных знаков, а **LaMa из IOPaint** (Sanster/IOPaint) — самый живой инструмент inpainting'а на GitHub — закрашивает найденные области, достраивая фон по соседям. Всё считается локально, без облаков и ключей.

**Установка и удаление — без терминала.** Кнопка «🧽 Убрать водяные знаки» на панели «Моих картинок» (и одноимённый пункт правого клика по ленте): если модуль ещё не установлен, программа честно предупредит о размере (iopaint + transformers + timm — вместе с PyTorch это гигабайты) и поставит всё pip-ом в скрытом окне, после чего сразу продолжит обработку. В меню «Модули» — установка/удаление одним пунктом (удаление с подтверждением, показом освобождаемого места и чисткой кэшей моделей — big-lama в torch-hub и Florence-2 в кэше Hugging Face; чужие кэши и общие с программой/rembg библиотеки не трогаются) и подменю детектора: Florence-2-base — быстрый (~0,5 ГБ), Florence-2-large — точнее (~1,6 ГБ). Модели (LaMa ~0,2 ГБ и Florence-2) скачиваются при первом запуске удаления.

**Установка чинится на новых Python (v0.8.12).** IOPaint требует ровно Pillow==9.5.0 — у этой версии нет готовых сборок под Python 3.12/3.13, из-за чего первая установка падала с «KeyError: '__version__'» на сборке старого Pillow. Теперь установка идёт в два шага: сам iopaint — без зависимостей, затем его зависимости из его же метаданных уже без требования Pillow — библиотека самой программы стоит и не перекладывается. «Удалить модуль» заодно вычищает и прямые зависимости iopaint (gradio, diffusers, peft, fastapi…), которые раньше оставались в системе.

**Как работает.** Выделенные плитки (или открытая картинка) обрабатываются одной сессией в фоне: модели грузятся в память один раз на пачку, на сетевом диске интерфейс не замирает. Результат — «имя_nowm.ext» рядом с оригиналом, формат сохраняется (AVIF → PNG), оригинал никогда не меняется, существующие файлы не затираются; файл уже-результат и GIF пропускаются. Область закраски — найденные боксы с запасом 15 px на сторону; файлы без найденных знаков честно считаются «чистыми» (результата нет, ошибки нет). Прогресс — в статусе, итоги — в статусе и «Журнале».

Тесты: новый `scripts/test_watermark.py` — 72 проверки; раздел в `scripts/test_modules_menu.py`.

## Пересборка выдачи поиска после удаления (v0.8.10)

При активном поиске по имени удаление картинок (Delete или контекстное меню) запускает поиск заново — по тому же принципу, что и перенос файлов в папки дерева (v0.8.5): удалённые файлы не остаются в выдаче «найденными», счётчик «Найдено: N» честный, а выдача, обрезанная по пределу 5000, добирает следующие подходящие файлы. Выделение встаёт на первую плитку новой выдачи, статус показывает и итог удаления, и ход пересборки. Без активного поиска поведение прежнее — лента просто худеет на удалённые плитки.

Тесты: `scripts/test_delete_restore.py` — новая секция с 7 проверками пересборки.

## Пипетка и закрашивание выделенной области (v0.8.8)

Кнопка **«💧 Пипетка»** на панели «Моих картинок» включает режим чтения цвета: наведение показывает цвет пикселя под курсором прямо в статусе («💧 #e02020 · 50,25»), клик берёт цвет — он копируется в буфер обмена как «#rrggbb», а на панели появляется образец (цветной квадрат + HEX). Быстрый путь без режимов: **правый клик по картинке берёт цвет в любом режиме** — в том числе прямо в режиме обрезки, не выходя из неё и не теряя выделение. Кнопка **«🪣 Закрасить»** (в режиме «✂ Обрезать», рядом с «💾 Как…») заливает выделенную рамкой область взятым цветом: результат виден сразу, запись отдельным файлом «имя_fill.ext» идёт в фоне рядом с оригиналом — оригинал не меняется, существующие файлы не затираются (свободный суффикс «-1»), при ошибке записи показ честно откатывается к оригиналу. Закрашивание непрозрачное — ровно тот цвет, что показывает образец; формат результата по расширению оригинала (AVIF → PNG, у JPEG/BMP прозрачность ложится на белый фон). GIF и пустой просмотр — кнопки погашены; Esc выходит из режима; итог — в статусе и «Журнале».

Тесты: новый `scripts/test_image_fill.py` — 67 проверок.

## Обрезка картинки мышью, как в XnView (v0.8.7)

Кнопка **«✂ Обрезать»** на панели «Моих картинок» включает режим обрезки: растяните рамку мышью прямо по картинке, поправьте её за восемь янтарных рукояток (углы и края) или перетащите целиком, схватив за внутреннюю область; внутри рамки — сетка третей, вне её картинка затемнена, у угла — бейдж с размером выделения, в статусе — «✂ 409×275 из 1920×1080». Клик по картинке без движения сбрасывает выделение, случайный клик не создаёт рамку. Как в XnView, три действия: **«💾 Сохранить»** записывает выделенную область отдельным файлом «имя_crop.ext» рядом с оригиналом, **«💾 Как…»** — через стандартный диалог с выбором имени и папки, **«✂▶ К следующему»** — сохраняет и сама открывает следующую картинку папки с чистой рамкой: папку целиком можно обрезать одним потоком, на последней картинке серия честно заканчивается. Выделение хранится в координатах картинки — зум и «◱ Вписать» в режиме работают, рамка остаётся на месте. Оригинал никогда не меняется, существующие файлы не затираются (свободный суффикс «-1»), вырезание и запись — фоновый поток (на сетевом диске окно не замирает), итог — в статусе и «Журнале». GIF-анимации не обрезаются (кнопка погашена), AVIF сохраняется как PNG, у JPEG/BMP прозрачность ложится на белый фон. Esc — выход из режима; режимы «⇲ Размер» и «✂ Обрезать» взаимоисключающие.

Тесты: новый `scripts/test_image_crop.py` — 74 проверки.

## Изменение размера картинки мышью (v0.8.6)

Кнопка **«⇲ Размер»** на панели «Моих картинок» включает режим, в котором размер картинки задаётся мышью прямо в окне предпросмотра: картинка обводится рамкой с тремя янтарными рукоятками — тяните угол (пропорционально) или правый/нижний край (одну сторону). Показ совпадает с будущим файлом один к одному: что видно, то и запишется; у угла рамки — бейдж с текущим размером, в статусной строке — «✂ 400×300 из 800×600». Кнопка **«💾 Сохранить»** записывает результат отдельным файлом «имя_ШxВ.ext» рядом с оригиналом: оригинал не меняется, существующие файлы не затираются (при конфликте — свободный суффикс «-1»), масштабирование и запись выполняет фоновый поток (на сетевом диске окно не замирает), после сохранения лента обновляется и сразу открывает новый файл. GIF-анимации в размере не меняются (кнопка погашена), AVIF сохраняется как PNG (Qt не пишет AVIF), у JPEG/BMP прозрачность ложится на белый фон. Esc или «◱ Вписать» — выход из режима.

Тесты: новый `scripts/test_image_resize.py` — 73 проверки.

## Перетаскивание выделенных файлов в папки дерева (v0.8.5)

Выделите картинки в ленте «Моих картинок» (Ctrl/Shift — как в Проводнике) и бросьте их на папку или диск в дереве слева — файлы перенесутся туда. Папка под курсором подсвечивается полупрозрачным цветом выделения; свёрнутая папка сама раскрывается, если подержать файл над ней (как в Проводнике). Перенос ничего не затирает: файлы, уже лежащие в целевой папке, пропускаются, а при конфликте имён файл получает свободное имя («cat-1.png»). Перенос — фоновая задача (окно не замирает даже на сетевом диске), итог и ошибки видны в статусе и «Журнале».

Тесты: новый `scripts/test_tree_drop.py`.

## Разрешение картинки в подписи плитки (v0.8.4)

Под именем файла на каждой плитке «Моих картинок» теперь выводится исходное разрешение картинки — тем же форматом «1920×1080», каким размер показывает полноэкранный просмотр; шрифт на шаг меньше и серый, чтобы не спорить с именем. Разрешение считывается из заголовка файла в фоновом потоке, вместе с миниатюрой (с учётом EXIF-поворота), и хранится прямо внутри кэшированной миниатюры — повторное открытие папки по-прежнему мгновенное и не читает файлы заново. Текст плитки остаётся чистым именем файла: переименование и поиск по имени работают как раньше.

Тесты: новый `scripts/test_thumb_caption.py`.

## Поиск с телефона: новые поисковики, мост из программы и журнал сервера (v0.8.3)

**Пять поисковиков вместо двух.** В шапке режима «Интернет» теперь: **Openverse** — официальный JSON-API агрегатора открытых картинок (Flickr, Wikimedia, NASA и сотни других источников: без ключа, без скрапинга, готовые миниатюры), **Wikimedia** — официальный API Commons, **DuckDuckGo** и **Bing** — серверный скрапинг там, где он ещё возможен (Bing всё чаще отдаёт пустую JS-оболочку — теперь это честная ошибка с подсказкой сменить поисковик, а не тихое «ничего не найдено»), и **«Программа»** — мост с вкладки «Поиск картинок»: программа ищет настоящим браузером, которому не страшны ни блокировки сетей, ни капчи, ни смена форматов выдачи, и автоматически передаёт телефону «очищенные и облегчённые» плитки — только ссылка на оригинал, превью, заголовок и страница-источник. Выбор поисковика запоминается; у запросов таймаут 60 с — вечного «Ищу…» больше не будет.

**Деятельность веб-сервера и API — в «Журнале» программы.** Открытие веб-интерфейса (с адресом клиента), поиск с телефона (движок, запрос, сколько нашлось, ошибки), переименование, удаление, запуск удаления фона, скачивание в папку и на устройство, отказы в режиме «только просмотр» — всё попадает и в журнал программы, и в журнал телефона. Миниатюры и листинги в журнал не пишутся — он не засоряется.

Тесты: секция интернет-поиска `scripts/test_server.py` — моки Openverse/Wikimedia/Bing (форматы m= и data-m=, пустая оболочка), мост «программа → телефон», события журнала (поиск/переименование/отказ), элементы интерфейса.

## Меню «Модули»: установка, удаление и настройки (v0.8.2)

Пункт **«Модули»** в строке меню (слева от «Справки») собирает управление всеми подключаемыми модулями в одном месте. Меню пересобирается при каждом открывании, поэтому состав и галочки всегда показывают актуальное состояние.

- **Удаление фона (rembg):** установка или удаление модуля одним пунктом (удаление — с подтверждением и показом, сколько занимают скачанные модели), подменю «Модель rembg» с галочкой на выбранной (u2netp / u2net / isnet-general-use). Заголовок раздела показывает, установлен ли модуль. Эти пункты убраны из контекстного меню ленты «Моих картинок» — там осталась только операция «🪄 Удалить фон».
- **Водяные знаки (Florence-2 + LaMa, v0.8.11):** установка или удаление модуля одним пунктом (с подтверждением, показом освобождаемого места и чисткой кэшей моделей), подменю «Модель детекции Florence-2» с галочкой на выбранной (base — быстрый / large — точнее). В контекстном меню ленты осталась только операция «🧽 Убрать водяные знаки».
- **Веб-сервер:** «▶ Запустить» / «⏹ Остановить» прямо из меню, галочка «Автостарт с программой» и пункт «🌐 Панель веб-сервера…» (порт, токен, QR-код, «только просмотр»). Заголовок раздела показывает состояние: «Сервер работает — порт N» или «остановлен».

## Веб-сервер: управление программой с телефона (v0.8.0)

Пункт **«🌐 Панель веб-сервера…»** в меню «Модули» открывает окно маленького веб-сервера — подключаемого и полностью удаляемого модуля (`app/server/`): телефон в той же сети открывает адрес с QR-кода и получает практически всю программу в мобильном интерфейсе. Запустить сервер можно и прямо из меню «Модули».

**Что доступно с телефона:** лента папок с миниатюрами (тот же дисковый кэш, что у программы), поиск по имени (вглубь подпапок, «игнорировать дефис»), полный просмотр со свайпами, переименование, удаление в корзину и окончательно, удаление фона rembg с прогрессом, диски и избранные папки, журнал.

**Безопасность:** доступ по токену (часть адреса, генерируется автоматически; после первого захода запоминается cookie), режим «только просмотр» запрещает удалённые изменения, есть ограничение корней для headless-запуска. Сервер работает, пока открыта программа, и гаснет вместе с ней; можно включить автостарт. Ничего не слушает и не занимает, пока вы не нажали «Запустить».

**Отдельный процесс** (headless, для папки без интерфейса): `python -m app.server --port 8477 --token МОЙ-ТОКЕН` — тот же API без GUI.

Тесты: `scripts/test_server.py` — реальные HTTP-запросы на случайном порту: токен (заголовок/ссылка/cookie), страница интерфейса, лента, кэш миниатюр (включая переиспользование кэша программы), Range/206, скачивание, правила переименования, удаление, «только просмотр», ограничение корней, поиск с пределом и дефисом, rembg-маршруты, менеджер настроек, CLI-процесс.

## Поиск картинок в интернете с телефона (v0.8.1)

Кнопка **🔎** в веб-интерфейсе переключает его в режим «Интернет»: запрос уходит поисковику (**DuckDuckGo** или **Bing** — выбор в шапке), плитки выдачи открываются в той же ленте, что и файлы. Отсюда можно открыть оригинал на весь экран (через сервер — сайты с проверкой Referer напрямую отдают картинку не всем), скачать оригинал на само устройство или сохранить в папку на компьютере — ту, что открыта в режиме «Файлы» (выбор помнится между заходами). Плитки отмечаются плюсиком — как чекбоксы выдачи в программе; плавающая кнопка «⬇ N» скачивает отмеченные одним фоновым заданием с прогрессом и журналом. Скачивание повторяет правила загрузчика программы: лестница попыток с Referer, раскрытие обёрток Cloudflare, имена без затираний («имя-1.ext»), лимит 100 МБ на файл. Поиск работает и в режиме «только просмотр» — он ничего не меняет на компьютере; сохранение в папку — недоступно. Поисковики — без встроенного браузера: сервер ходит по адресам с чистыми данными (JSON-выдача DuckDuckGo, серверный HTML Bing) — новый модуль `app/server/websearch.py`.

Тесты: секция интернет-поиска в `scripts/test_server.py` — локальный мок-сервер изображает выдачу DuckDuckGo/Bing и сайт с картинками (сеть не нужна): разбор плиток, дедупликация, offset, прокси с attachment, фоновое скачивание с правилами имён, «только просмотр», ограничение корней.

## Быстрая работа в сети и с сетевыми дисками

Image Hunter изначально писался под сценарий «фотографии лежат на сетевом диске (NAS, Windows-шара, смонтированная папка), а канал не резиновый». Обычные просмотрщики на таком сценарии «умирают»: список из 10 000 файлов — это 10 000 запросов stat по сети, а массовая прогрузка миниатюр забивает канал целиком. Ниже — что именно сделано и почему это работает.

**1. Папка читается одним проходом — без stat каждого файла.** Классический подход `os.listdir()` + `os.stat()` на каждый файл превращается в SMB-сети в две сетевые операции на файл. Image Hunter использует `os.scandir()`: тип файла, размер и время изменения приходят вместе с перечислением — вход в папку это одна сетевая операция, сколько бы файлов в ней ни было. Скрытые файлы и картинки отфильтровываются по этим же данным, без единого лишнего запроса.

**2. Ленивые миниатюры: грузится только то, что видно.** Массовая прогрузка предпросмотра отключена полностью. Миниатюры строятся только для видимой части списка (плюс запас на высоту окна); при прокрутке догружается новая порция, при обратной прокрутке ничего не перечитывается. Открыли сетевую папку — программа запросила у сети ровно те файлы, которые попали на экран (шесть из тысячи в типовом окне). Кнопка-выключатель «🖼 Миниатюры» отключает предпросмотр совсем — состояние запоминается между запусками.

**3. Дисковый кэш миниатюр — повторное открытие мгновенно.** Каждая готовая миниатюра пишется в `%LOCALAPPDATA%\ImageHunter\thumbs` (Linux: `~/.cache/ImageHunter/thumbs`). Ключ — SHA-1 от «путь + размер + mtime»: изменился файл — кэш сам устареет, обслуживать его не нужно. Повторное открытие той же сетевой папки отрисовывается из локального кэша и не делает ни одного обращения к сети за картинками. Лимит кэша 256 МБ, запись атомарная (через временный файл) — обрыв связи не оставит битых миниатюр.

**4. Поколения задач: ушёл из папки — лишнее молча отбрасывается.** Каждому сканированию присваивается номер-«поколение». Миниатюры и результаты поиска прошлой папки, пришедшие с опозданием, отбрасываются: очередь задач не копится, сеть не гоняет уже ненужное.

**5. Поиск по подпапкам — в фоне, без блокировки окна.** Поиск по имени идёт в фоновом потоке тем же «однопроходным» scandir и отдаёт результаты по мере обхода: окно остаётся отзывчивым, сеть нагружается равномерно, миниатюры при поиске не читаются.

**6. Интерфейс — настроил один раз.** Ширина дерева папок и ленты миниатюр запоминается между запусками; иконки отдаются в список батчами — сотни новых строк не вызывают лавину перерисовок.

**7. Сеть в загрузках — быстро, но вежливо.** Скачивание — до 6 файлов параллельно в QThreadPool, стриминговая запись чанками по 64 КБ (файл не копится в памяти), таймауты 10/60 с, лимит 100 МБ на файл. WebP-сохранение работает в 3 потока — щадяще к сайтам-источникам.

**8. Обновление в обход кэша CDN.** Установщик и проверка обновлений качают код через `codeload.github.com`, который генерирует архив на лету: новая версия доступна сразу после пуша, без 5-минутного кэша `raw.githubusercontent.com`.

## Мгновенный запуск и защита от зависаний (v0.7.0)

Главный источник тяжести и зависаний в Image Hunter — встроенный браузер вкладок поиска: каждый QWebEngineView это целый процесс Chromium. Начиная с v0.7.0 архитектура модульная и ленивая — тяжелое запускается только тогда, когда оно реально нужно:

**1. Ноль Chromium на старте программы.** Раньше каждая вкладка поиска при запуске сразу создавала браузер и открывала стартовую страницу: восстановление 11 вкладок = 11 процессов Chromium и 11 одновременных загрузок — на слабой машине или плохой сети это выглядело как зависание. Теперь вкладка при старте — это только её панель инструментов (несколько килобайт интерфейса). Браузер вкладки создаётся в момент первого показа вкладки (`showEvent`). Пока вы не открыли вкладку «Поиск картинок», Chromium вообще не запускается — окно появляется мгновенно.

**2. «Найти везде» без шторма загрузок.** Поиск сразу во всех поисковиках больше не запускает десяток загрузок одновременно: у вкладок без браузера запрос лишь запоминается (pending) и выполняется, когда вы вкладку открываете. Сеть, память и процессор расходуются ровно на то, что вы смотрите; вкладка, которую вы так и не открыли, не потратила ни мегабайта.

**3. Вся настройка WebEngine — в одном модуле.** `app/core/webengine.py` — единая точка: ловля предупреждений платформы (поломанный Wayland), флаги `--disable-gpu` (автодетект, IH_GPU), `--disable-dev-shm-usage` (на системах с крошечным /dev/shm вкладки молча падали и перезапускались по кругу), `--disable-breakpad`, и `--no-sandbox` — только когда ядро запрещает пользовательские пространства имён (иначе вкладки циклически падают и выглядят зависшими; отключение видно в «Журнале», вернуть песочницу — `IH_NO_SANDBOX=0`).

**4. Watchdog «вечной» загрузки.** Страница, не открывшаяся за 45 секунд (мёртвая сеть, зависший редирект), останавливается автоматически — вкладка никогда не крутит бесконечную загрузку, и в «Журнале» видно, какой адрес не открылся.

**5. Данные поисковиков — отдельный модуль.** Список поисковиков, шаблоны адресов и распознавание страниц выдачи переехали в `app/core/engines.py` — чистые данные без интерфейса: их можно переиспользовать где угодно и тестировать без Qt.

## Сетевые диски и большие папки: зависания исключены (v0.7.2)

Диагноз из «Журнала» (строки ⏱ и «⚠ Интерфейс не отвечал») показал: на WebDAV-диске (Z:) зависали и миниатюры, и открытие папки — процесс замирал целиком на сетевой тайм-аут (~60 с). В v0.7.2 ни одна сетевая операция больше не касается GUI-потока и Qt-файлового чтения:

**1. Картинки читаются питоновским I/O, декодируются из памяти.** `app/core/imgload.py` сначала читает файл целиком обычным `open().read()` — CPython отпускает GIL на чтении, поэтому подвисший по сети файл держит только рабочий поток, а интерфейс и остальные потоки живут. Декод — из памяти (QImageReader по QBuffer, AVIF — Pillow): заодно файл проходится один раз, а не два-три, как это делал QImageReader по пути (size() + read() + проверка AVIF) — на сетевом диске это втрое меньше обращений.

**2. Открытие папки — асинхронно.** Скан папки (os.scandir по сети) выполняет рабочий поток: клик по папке или «Открыть папку…» сразу очищает ленту и показывает «Читаю папку…», а файлы появляются по готовности. Пока идёт скан, можно менять папки — устаревший результат отбрасывается. Автопоказ последней папки при запуске тоже сканируется в фоне — старт мгновенный даже на сетевом диске.

**3. Дерево папок догружается из фона.** Клик и раскрытие узла больше не ждут scandir: подпапки появляются, когда прочитаются (до этого узел выглядит раскрываемым). Синхронное чтение осталось только там, где результат нужен немедленно, — в фильтре папок и подсветке текущей папки.

**4. Сетевые миниатюры — отдельный узкий пул.** Чтение файлов с подключённых дисков (Windows, DRIVE_REMOTE — WebDAV/SMB) идёт через пул на 2 потока: когда сервер подвис, ждут одна-две задачи, а локальные миниатюры продолжают грузиться. Просмотр полного размера — по той же схеме.

**5. Удаление — в фоне.** Корзина и окончательное удаление выполняются рабочим потоком (диалоги — по-прежнему в GUI): удаление кучи файлов по сети больше не останавливает окно. Неудачи корзины, как и раньше, честно спрашивают про окончательное удаление.

**6. Честные формулировки в «Журнале».** Медленные операции из рабочих потоков помечаются «⏱ МЕДЛЕННО (фоном, интерфейс жив)», а «…это блокирует интерфейс» остаётся только у операций, реально замерших в GUI-потоке, — по журналу сразу видно, где именно зависало.

## Чекбоксы на Google и Mail.ru снова работают (v0.7.3)

Оба случая — не «сломалось вообще», а смена разметки поисковиками, из-за которой инъекция чекбоксов перестала доходить до плиток:

**1. Mail.ru объединил поисковый портал.** Адрес `go.mail.ru/search_images` теперь редиректит на `mail.ru/search?...&type=images`, а сама выдача картинок открывается вложенным фреймом `yandex.ru/images` внутри. Прежний гейт «инъекция только если главная страница — выдача» навсегда отсекал Mail.ru: адрес-обёртка выдачей не является. Теперь фреймы-выдачи ищутся независимо от адреса обёртки: инъекция и счётчик отмеченных работают с любой страницей, у которой внутри есть фрейм с выдачей, а в списке поисковиков Mail.ru сразу открывает конечный адрес `mail.ru/search?text=…&type=images` (без лишнего редиректа).

**2. Google снова сменил разметку плиток.** Хешированные классы Google меняются от релиза к релизу, и селектор конкретного класса рано или поздно перестаёт совпадать. Вместо лотереи с именами классов чекбокс теперь «поднимается» по качеству: если контейнер не похож на плитку, а лучшим кандидатом является только миниатюра, скан перебирает родителей и берёт минимальную обёртку, у которой известен настоящий оригинал (якорь `/imgres?imgurl=…`), — но не выше обёрток, захватывающих чужие плитки. Один чекбокс на плитку, оригинал — по-прежнему оригинал.

**3. Диагностика в «Журнале».** После инъекции в журнал пишется строка «Выдача: плиток с чекбоксами: N (фреймов: M)», а если плитки не распознаны — «Выдача найдена, но плиток для чекбоксов не распознано… пришлите журнал разработчику»: следующий отчёт о пропавших чекбоксах сразу отвечает, дошла ли инъекция и сколько плиток распознано.

Кроме того, `udm=2` признаётся выдачей на любом национальном домене Google (google.de, google.co.uk, …) — Google сам переезжает между ними; скан чекбоксов изолирован по плиткам (одна битая плитка больше не рушит весь скан).

## Фильтр по имени не сбрасывается после скачивания (v0.7.5)

Сценарий: в «Моих картинках» активен поиск по имени, из «Поиска картинок» в ту же папку сохраняется пачка картинок — и при возврате во вкладку лента показана уже без фильтра, хотя запрос в поле остался; приходилось ещё раз нажимать Enter. Причина: сохранение вызывает `refresh()` текущей папки, а тот перечитывал папку простым сканом, игнорируя активный запрос. Теперь `refresh()` работает как клик по дереву: при активном поиске он заново запускает поиск от той же папки — новая порция файлов дописывается в ту же выдачу, ничего перенабирать не нужно. Без запроса поведение прежнее — папка перечитывается целиком.

## Переименование файлов — F2, двойной клик по имени и пункт меню (v0.7.17)

Пожелание: «добавь возможность переименовывать файлы, как по меню мыши, так и 2-я кликами на название файла».

Имена картинок правятся прямо в ленте «Моих картинок», не выходя из программы: пункт «✏️ Переименовать» в правом клике по плитке, клавиша **F2** или двойной клик по **имени файла** под миниатюрой. Редактор открывается с выделенным именем без расширения (как в Проводнике) — Enter или клик мимо применяют правку, Esc отменяет. Двойной клик по самой картинке по-прежнему открывает её в системном просмотрщике. Из выделенных переименовывается файл под курсором, как в Проводнике. Само переименование идёт в рабочем потоке (на сетевом диске окно не замирает), лента и статус открытой картинки обновляются сразу. Новое имя проверяется заранее: пустое, с точкой/пробелом на конце или с запрещёнными Windows символами (`\ / : * ? " < > |`) принято не будет, а конфликт с существующим файлом вернёт старое имя с объяснением в строке статуса. Каждый итог — в «Журнале» (переименовано/ошибка с причиной).

Тесты: `scripts/test_rename.py` — геометрия подписи плитки, маршрутизация двойного клика (имя → редактор, картинка → открытие), полный цикл переименования (файл на диске, `_paths`, плитка, статус), F2-шорткат, пункт меню, запрет пустых и запрещённых имён, конфликт с существующим файлом, переименование «только регистр», обновление статуса открытой картинки, смоук версии.

## Фон прозрачных картинок — «шахматка» с ползунком (v0.7.16)

Пожелание из работы: «пусть фоном для прозрачных форматов будет регулируемая по размеру ползунком сетка из серых и белых квадратов».

Под прозрачными картинками (PNG, GIF, WebP, результат «*_nobg.png»…) область просмотра теперь рисует классическую «шахматку» — белые и серые квадраты, как «прозрачный холст» в графических редакторах. Сразу видно, где картинка прозрачна, а где нарисован белый фон — раньше и то и другое сливалось с тёмной подложкой. Размер клеток регулируется ползунком на панели (иконка-шахматка рядом подсказывает, что он крутит), выбор запоминается между запусками. Шахматка включается только для картинок с альфа-каналом: у JPEG и других непрозрачных форматов подложка остаётся прежней тёмной. Квадраты едут вместе с картинкой при прокрутке (рисуются от начала виджета-картинки, как холст), на HiDPI-экранах остаются резкими; под сообщениями («Откройте папку…», ошибки чтения) квадраты не рисуются. Превью в окне выбора после удаления фона (v0.7.15) теперь использует те же цвета и тот же размер клетки, что и просмотр.

Тесты: `scripts/test_checker.py` — цвета и геометрия плитки (белый/серый по диагонали, HiDPI), отрисовка поверх QLabel (прозрачный пиксель показывает квадрат), включение по альфа-каналу PNG и выключение для JPEG, ползунок (пределы, запоминание в настройках, перестройка плитки), текст без шахматки, превью выбора с клеткой из настроек.

## Результат удаления фона можно вернуть; модуль рассказывает о себе в статусной строке (v0.7.15)

Два пожелания из работы: «сделай, чтобы был выбор — сохранять файл после изменения фона или вернуть оригинал» и «пусть в статусной строке будет информация о том, что делает модуль удаления фона — скачивается модель или нет, статус загрузки».

**Выбор после удаления фона.** Когда пачка обработана, программа больше не просто оставляет файлы «*_nobg.png» рядом с оригиналами — внизу открывается окно с вопросом «Сохранить результат или вернуть оригиналы?». В окне — превью первого результата на «шахматке» (прозрачность видна сразу) и имя файла; если результатов несколько — «…и ещё N». Окно намеренно немодальное: пока оно открыто, лента миниатюр кликается, и каждый результат «*_nobg.png» можно открыть в полном размере и рассмотреть. Кнопка «💾 Сохранить результат» оставляет файлы; кнопка «↩ Вернуть оригиналы» удаляет результаты **только этой пачки** — оригиналы не менялись никогда, так что «вернуть» безопасно (результаты созданы программой секунды назад и удаляются мимо корзины, не засоряя её). Закрытие крестиком или Esc — это тоже «Сохранить»: результат теряется только по явному клику. Если запустить новую пачку, не ответив на старый вопрос, он закрывается как «Сохранить». Каждый выбор пишется в журнал (сохранено/возвращено/ошибки по файлам), после возврата лента сразу перечитывается.

**Статусная строка рассказывает про модуль.** Прежде скачивание модели шло через pooch, чей прогресс живёт в консоли — у программы её нет, и пользователь сидел в тишине, пока качаются 5–176 МБ (а на pythonw-версии tqdm ещё и падал, пока v0.7.14 не подставил заглушки). Теперь программа перехватывает скачивание: модель качается самим приложением через requests, и статусная строка показывает весь путь модуля — «Готовится модель u2netp…» → «Скачивается модель u2netp: 1,2 МБ из 4,7 МБ (26 %)» → «Модель u2netp скачана (4,7 МБ)» → «Модель u2netp готова» → «Удаление фона: 2/5 — cat.jpg…». Скачанный файл всё равно проверяет pooch (хеш), при обрыве сети недокачанный «.part» подчищается и скачивание повторяет pooch — прогресс станет тише, но модель скачается. Итог скачивания (размер, время) пишется в журнал; тики процентов — только в статусную строку, журнал не засоряют.

Тесты: `scripts/test_rembg.py` — 134 проверки, включая сквозной прогон с настоящим rembg (пустой кэш моделей → сигналы скачивания → файл-результат → выбор), юнит потокового скачивания с обрывом сети, обёртки pooch и возврата оригиналов.

## Удаление фона работает без консоли; запуск без замираний на сетевом диске (v0.7.14)

Два репорта из работы исправлены: «🪄 Не удалось убрать фон — 'NoneType' object has no attribute 'write'» (удаление фона не работало вовсе) и «⚠ Интерфейс не отвечал ≈1742 мс» при старте.

**Удаление фона на Windows без консоли.** Программа запускается через pythonw — консоли нет, и в Python `sys.stdout`/`sys.stderr` равны `None`. Скачивание модели rembg идёт через pooch с прогресс-баром tqdm, а tqdm пишет в `sys.stderr` и падал с «'NoneType' object has no attribute 'write'»: модель не сохранялась, и каждая попытка повторяла ошибку (первая тратила минуту на медленное соединение с GitHub, вторая падала мгновенно). Перед обработкой теперь подставляются заглушки, пишущие в никуда (`_ensure_stdio`); настоящая консоль не трогается, вызов идемпотентен.

**Дерево дисков читается фоном.** Список дисков строился `QStorageInfo` прямо в GUI-потоке: первый запрос к ещё не подключённому сетевому диску устанавливал SMB-сессию — окно замирало на пару секунд (то самое «≈1742 мс»). Теперь тома перечисляет рабочий поток (_DrivesTask): дерево появляется сразу, секция дисков достраивается, когда список готов; при повторных пересборках (смена языка, ⟳) диски восстанавливаются из кэша мгновенно. Если набор дисков не изменился — секция не трогается вовсе (раскрытые ветви не сворачиваются), обновляется только статистика объёма в подсказках. Подсветка текущей папки после пересборки стала асинхронной прогулкой (принцип v0.7.6), а синхронная подсветка умеет перечитать узел, у которого фоновая догрузка ещё не успела (жетон отменяет поздний результат).

Тесты: `scripts/test_rembg.py` — 63 проверки, включая точный сценарий (кэш моделей пуст, stdio = None → модель скачалась, файл-результат создан); test_tree — мгновенное восстановление дисков из кэша, фоновое перечисление, скрытие виртуальных томов; test_folder_search — ожидания перестроены под асинхронное дерево.

## Текущее задание видно внизу, в статусной строке (v0.7.13)

Журнал собирает всю хронику работы, но вкладку ещё нужно открыть. Теперь каждая строка журнала (события, предупреждения, ошибки) дублируется в левую часть статусной строки внизу окна: что бы ни делала программа — ищет, скачивает, удаляет фон, ставит или убирает модуль rembg, синхронизирует дерево дисков — текущее задание видно без переключения вкладок.

События из рабочих потоков (поиск, загрузка, миниатюры) доезжают до статусной строки через очередь Qt-сигналов — строка меняется в темпе работы, интерфейс не замирает. Правила показа простые: DEBUG не показывается (технический шум), многострочные записи вроде трассировок ошибок показываются первой строкой, слишком длинные — обрезаются до 220 символов. Сообщение держится, пока его не сменит следующее событие: программа «рассказывает», чем занята, и не гаснет через пять секунд посреди долгой установки модуля.

Прочие элементы статусной строки (статус «Моих картинок» справа, выбор языка и кнопка обновления) не тронуты. Тесты: `scripts/test_status_log.py` — 12 проверок, включая событие из рабочего потока и то, что стартовое «Готово» не затирается.

## Удаление фона прямо из программы: rembg как модуль (v0.7.12)

У картинок с маркетплейсов и из поиска часто хочется убрать фон. Подключён **rembg** (github.com/danielgatis/rembg) — самый живой открытый проект удаления фона: код под MIT, всё считается локально через ONNX Runtime, без облаков и ключей.

**Установка без терминала.** Кнопка «🪄 Удалить фон» на панели «Моих картинок» и одноимённый пункт в правом клике по ленте: если модуль ещё не установлен, программа сама предложит поставить пакет `rembg[cpu]` (pip в скрытом окне, как обновление из v0.7.6) и **сразу продолжит удаление фона** по той картинке, на которую кликнули. Пункт «Установить модуль удаления фона…» есть и в самом меню правого клика.

**Удаление модуля — тоже из программы.** В том же меню: «Удалить модуль rembg и модели…» — pip удаляет пакет и ONNX Runtime, затем вычищается кэш скачанных моделей (`~/.rembg`, у старых версий `~/.u2net`); перед удалением программа показывает, сколько места освободится. На диске не остаётся ничего.

**Как работает.** Результат сохраняется рядом с оригиналом как `имя_nobg.png` и сразу появляется в ленте; повторная обработка результата блокируется («это уже картинка без фона»). Работает и по выделению — несколько плиток за раз. Обработка идёт в рабочем потоке (одна сессия rembg на всю пачку — модель грузится в память один раз), на сетевых дисках файлы читает узкий пул — интерфейс не замирает. Прогресс — в строке статуса, итоги и ошибки по каждому файлу — в журнале. Выбор модели — в подменю «Модель»: `u2netp` (~5 МБ, быстрая, по умолчанию), `u2net` (~176 МБ), `isnet-general-use` (~170 МБ, самые чистые края); модель при первом запуске скачивается автоматически и запоминается между сеансами.

Тесты: `scripts/test_rembg.py` — 60 проверок, включая сквозной прогон с настоящим rembg (установка pip → скачивание модели → файл-результат → чистка кэша).

## Стабильность и скорость: итоги полного аудита кода (v0.7.11)

Пройден весь код заново — на предмет зависаний, гонок и медленных мест. Найдено и исправлено восемь узких мест:

**1. GIF больше не читается в интерфейсе.** Полные картинки декодируются в фоне с v0.7.2, но GIF шёл мимо: `QMovie` открывает файл прямо в GUI-потоке, и на подвисшем сетевом диске даже чтение заголовка замораживало окно на сетевой тайм-аут. Теперь GIF-файл читается в рабочем потоке (тем же питоновским I/O, который отпускает GIL), а анимация строится из памяти поверх `QBuffer` — последнее чтение файла в GUI-потоке закрыто.

**2. Параллельные скачивания больше не затирают друг друга.** Имя файла берётся из ссылки, и у шести параллельных загрузок с разных адресов оно нередко совпадает (`image.jpg`): классическая проверка «есть ли файл → создать» не видит гонок, и один файл молча перезаписывал другой. Теперь файл создаётся атомарно средствами ОС (`O_CREAT|O_EXCL`): проигравший поток честно берёт следующий свободный номер (`image-1.jpg`, `image-2.jpg`…), ничего не пропадает.

**3. Повторное использование соединений.** Каждый запрос открывал новое TCP/TLS-соединение: пачка из сотни картинок с одного CDN платила рукопожатие за каждую. Теперь у каждого рабочего потока своя сессия `requests` — соединения переиспользуются, пачки качаются заметно быстрее, а сокеты не копятся в `TIME_WAIT`. Неудачные ответы закрываются сразу, а не ждут сборщика мусора.

**4. Подсветка «Открыть папку…» — без замираний.** Выбор папки через диалог подсвечивал её в дереве синхронно: на сетевом диске каждый уровень пути платил сканом в GUI-потоке. Теперь подсветка идёт асинхронной прогулкой (той же, что при запуске программы с v0.7.6) — и при сохранении пачки в новую папку тоже.

**5. Ресайз окна с большим фото без подлагиваний.** Перетаскивание края окна пересчитывало картинку «по размеру окна» на каждый пиксель, а плавное масштабирование большого фото стоит десятки миллисекунд — подлагивания складывались в заметное торможение. Теперь пересчёт происходит один раз, когда окно перестало меняться.

**6. «Обновить» без дублей.** Двойной клик по кнопке обновления запускал две сетевые проверки и показывал два диалога подряд. Теперь, пока проверка не закончилась, повторные клики ничего не запускают.

**7. Корзина спрашивается один раз на диск.** Перед удалением программа уточняет, есть ли на диске корзина; при выделении сотни файлов запрос уходил в shell за каждым файлом. Результат запоминается по корню диска.

**8. Отчёт об удалении стал честным.** На диске без корзины удаление «навсегда» учитывалось в статусе и журнале как «перемещено в корзину»: счёт вёлся по номеру фазы удаления, а не по фактическому режиму. Теперь «Удалено окончательно: N» и событие журнала `delete_perm` проставляются по-настоящему.

**9. Кэш-мелочи для сети уже на месте** (v0.7.2–v0.7.10): сетевость диска, наличие корзины, ленивые миниатюры, фоновые сканы и порционный поиск — аудит подтвердил, что эти механизмы работают как задумано.

## Фильтр папок ищет в выделенной папке или диске (v0.7.10)

**1. Область поиска — фокус.** Раньше буквы в «🔍 Фильтр папок…» запускали обход всех ветвей дерева разом — Дома, избранного и всех дисков, включая сетевые: на WebDAV/SMB поиск растягивался на долгие секунды, а в результатах мелькало «лишнее» из чужих дисков. Теперь ищется вглубь того, что подсвечено в дереве: выделили диск Z: — фильтр обыщет весь этот диск, выделили папку «Автозапчасти» — только её подпапки. Чужие ветки прячутся целиком и не обходятся вовсе — на сетевом диске это вся экономия. Ничего не выделено — поиск по всем дискам, как раньше. В счётчике над деревом видно, где искали: «Найдено папок: 2 — в «Z:/Автозапчасти»».

**2. Смена фокуса перевыбирает область.** Клик по другой папке или диску при активном фильтре сразу переприменяет его к новой области (раньше при том же тексте фильтр просто не перезапускался). Enter открывает только совпадения внутри области — в чужой диск он не уведёт.

В баг-репорте достаточно прислать журнал: сразу видно, у кого именно что случилось.

Информация о поиске — в строке статуса.** Раньше результат поиска по имени («Поиск «96985730»: 0 файлов») рисовался в той же верхней панели, что и поле поиска: длинные тексты распирали панель, а взгляд за результатом бегал по окну. ## Обновление без терминалов и дерево, показывающее, где вы (v0.7.6)

**1. Обновление из приложения — ноль окон терминала.** Раньше установка шла в видимом окне консоли (а до v0.7.4 — и вовсе в двух-трёх), и окна оставались на экране после обновления. Теперь cmd запускается со специальным флагом CREATE_NO_WINDOW: терминалов нет ни во время обновления, ни после него. Вывод установщика пишется в журнал `%TEMP%\ImageHunter_update.log`; при сбое вместо консоли показывается обычный диалог с ошибкой и путём к журналу. Заодно пути установки больше не вписываются в батник, а передаются через переменные окружения — обновление не ломается, если установка или имя пользователя с кириллицей. О том, чего ждать, приложение сообщает само: после подтверждения обновления появляется окно «обновление пройдёт в фоне, приложение закроется и запустится само через 1–2 минуты».

**2. Дерево папок раскрывается к текущей папке.** Если при старте восстановились последняя папка и фильтр по имени, раньше было не видно, где лежат показанные картинки, — дерево оставалось свёрнутым. Причина: подсветка дерева была привязана к результату фонового скана папки, а восстановленный поиск обгонял скан и отбрасывал его вместе с подсветкой. Теперь дерево раскрывается к текущей папке сразу, уровень за уровнем, в фоне (на сетевом диске — без замираний интерфейса); если папка недоступна, подсвечивается ближайший существующий узел; ручной выбор и открытие через диалог перебивают прогулку, а не наоборот.

## Возможности

**📁 Мои картинки** — локальный просмотрщик:
- **дерево дисков и папок слева**: смонтированные диски и устройства (со свободным местом в подсказке),
  избранные папки ⭐ — всегда вверху, быстрые ссылки «Домой» и «Изображения»; папки раскрываются лениво,
  клик по папке — сразу показать её картинки;
  ширина панели регулируется мышью; кнопка «⟳» обновляет список дисков (после подключения флешки);
- **фильтр папок**: поле «🔍 Фильтр папок…» над деревом — пока вы вводите буквы, в дереве остаются только папки,
  в имени которых они есть: остальные скрываются, ветки к совпавшим раскрываются, над деревом видно, сколько
  папок нашлось и где искали; ищет вглубь выделенной папки или диска (что подсвечено в дереве — то и обыскивается;
  ничего не выделено — все диски); работает мгновенно и не сканирует диск заново — дерево лишь догружает уровни в
  пределах бюджета (300 папок или 1,5 с за раз), поэтому даже огромный или сетевой диск не подвесит окно;
  регистр не важен, клик открывает папку, Enter — первую найденную, Esc — сброс; скрытые папки не показываются;
- **ленивые миниатюры**: грузятся только для видимой части списка (при прокрутке догружаются
  остальные) — вход в сетевую папку с тысячами фотографий больше не читает все файлы подряд
  и не забивает сеть; под именем файла на плитке — разрешение картинки («1920×1080»);
  кнопка-выключатель «🖼 Миниатюры» полностью отключает предпросмотр
  (состояние запоминается между запусками); миниатюры кэшируются на диске
  (`%LOCALAPPDATA%\ImageHunter\thumbs` / `~/.cache/ImageHunter/thumbs`), поэтому повторное
  открытие папки — в том числе сетевой — почти мгновенное; папки сканируются одним проходом,
  без «стата» каждого файла (быстро даже по SMB-диску);
- **выделение и drag'n'drop**: выделите картинки в ленте (Ctrl/Shift — как в Проводнике)
  и перетащите их мышью в Проводник, почту или другое приложение — либо бросьте
  на папку или диск в дереве слева, чтобы переместить их туда (v0.8.5); передаются
  оригинальные файлы (`text/uri-list`); запуск перетаскивания подстрахован тремя
  независимыми путями (фильтр событий, собственный перехват движения мыши, встроенная
  механика Qt), а каждый шаг пишется в «Журнал»; **если тянуть не получается —
  запасной путь без драга:** `Ctrl+C` (или правый клик → «Копировать выделенные файлы»),
  затем вставьте их куда нужно — `Ctrl+V` в Проводник или браузер;
- **поиск по имени файла**: введите часть имени в поле сверху — найдутся все картинки
  в текущей папке и всех подпапках; без масок и `*`, регистр не важен, результаты
  появляются сразу в процессе обхода; поле можно расширить мышкой — потяните за его
  левый или правый край (курсор превратится в «↔»), ширина запомнится между запусками;
  чекбокс **«игнорировать дефис»**: поиск не различает дефисы — запрос «23542-23523»
  найдёт и «2354223523», и «23542-23523» (артикулы запчастей пишут то с дефисом,
  то без, и не всегда на том же месте); состояние чекбокса запоминается;
- **удаление файлов**: клавиша `Delete` или правый клик → «🗑 Удалить» —
  выделенные картинки перемещаются в корзину (восстановимо из Проводника); подтверждение
  с числом файлов, каждая неудача — с причиной в журнале. На дисках без корзины
  (сетевые, часть съёмных) программа предлагает удалить окончательно — с отдельным
  подтверждением;
- при запуске автоматически открывается последняя папка (если в ней до 2000 картинок)
  и восстанавливается последний запрос поиска — как перед закрытием;
- полноэкранный просмотр, зум (`+` / `−` / `Ctrl+колесо`), «вписать в окно», «100%»;
- навигация стрелками ←/→, сортировка «по-человечески» (file2 < file10);
- **поддержка AVIF**: файлы `.avif` видны в ленте с миниатюрами и полноэкранным просмотром,
  а AVIF-картинки, скачанные по ссылкам (маркетплейсы отдают AVIF даже под именем `.jpg`),
  перекодируются в любой из форматов; декодер — Pillow + pillow-avif-plugin (ставится автоматически);
- просмотр выбранной картинки грузится в фоновом потоке — выбор файла на сетевом диске
  (как и чтение тяжёлого AVIF) больше не подвешивает окно («Не отвечает»);
- анимированные GIF, поддержка JPG/PNG/WEBP/BMP/GIF/AVIF;
- двойной клик по миниатюре — открыть файл системным просмотрщиком; кнопка «Показать в проводнике»;
- лента миниатюр растягивается мышью за разделитель (ширина панелей запоминается между запусками),
  поле поиска находится справа на панели инструментов и тоже меняет ширину мышью — за левый/правый край.

**🌐 Поиск картинок** — встроенный браузер (Chromium):
- **мультивкладки «как в браузере»**: «＋»/Ctrl+T — ещё одна вкладка поиска, у каждой свои
  поисковик и браузер; правый клик по вкладке — дублировать / закрыть / закрыть другие /
  закрыть справа; крестик закрывает вкладку (последнюю заменяет свежая), вкладки
  перетаскиваются мышью; заголовок вкладки — выбранный поисковик, а кружок — его
  фирменный цвет (Яндекс — красный, DuckDuckGo — оранжевый, Google — синий,
  Bing — зелёный); открытые вкладки восстанавливаются при следующем запуске;
- **одно поле — все поисковики**: общая строка запроса над вкладками; Enter или
  **«🔎 Найти везде»** — запрос открывается сразу во всех 11 поисковиках,
  у каждого своя вкладка с выдачей (уже открытые вкладки обновятся);
- поисковики (11): Яндекс.Картинки, Google, Bing, DuckDuckGo (безопасный режим),
  Brave, Startpage, Mojeek, Baidu, Sogou, Naver, Mail.ru;
- капчу Яндекса можно вводить прямо во встроенном браузере;
- **чекбоксы на плитках выдачи**: отметьте оранжевыми галочками нужные картинки —
  на кнопке появится счётчик, а по **«Скачать отмеченные»** скачаются большие оригиналы
  (у Яндекса берётся `origUrl` — тот же файл, что открывается при клике на превью,
  например `avatars.mds.yandex.net/get-mpic/…/orig`; для остальных поисковиков —
  оригинал из параметров ссылок плиток);
- чекбоксы работают на актуальной разметке DuckDuckGo (2025): плитки без привычных
  классов, а «оригиналы» — из кеша Bing без расширения в имени файла — распознаются
  и отмечаются;
- чекбоксы работают и на актуальной выдаче Google (udm=2): миниатюры
  `encrypted-tbn0.gstatic.com`/`googleusercontent` без расширения распознаются,
  ленивые плитки (картинка подгружается позже отрисовки) получают галочку,
  а непрерывная перерисовка выдачи больше не откладывает появление чекбоксов;
- чекбоксы работают и на актуальной выдаче Brave (прокси-миниатюры
  `imgs.search.brave.com` без расширения — настоящий оригинал распаковывается
  из base64 в пути), Sogou (классы плиток и атрибут `drag-img`) и Mail.ru
  (выдача открыта во вложенном фрейме — чекбоксы и сбор ссылок работают
  и во фреймах). Mail.ru объединил поисковый портал: go.mail.ru/search_images
  теперь редиректит на mail.ru/search?type=images — этот адрес тоже считается
  выдачей, а инъекция больше не привязана к адресу страницы-обёртки;
- если поисковик меняет разметку плиток (Google регулярно меняет хешированные
  классы), чекбокс «поднимается» от миниатюры к ближайшей обёртке, у которой
  известен настоящий оригинал — галочки и оригиналы не теряются;
- в «Журнале» видна диагностика чекбоксов: сколько плиток с галочками
  установлено на выдаче (или «не распознано ни одной» — пришлите журнал
  разработчику);
- чекбоксы подхватывают плитки, догружаемые при прокрутке выдачи;
- кнопка **«✕ Снять отметки»** — снимает все оранжевые галочки с плиток одним нажатием
  (активна, когда есть хоть одна отметка);
- кнопка **«Собрать ссылки»** — как раньше: все картинки открытой страницы (миниатюры, оригиналы
  из прокси DuckDuckGo, из `data-bem`/`data-state` JSON Яндекса) одной пачкой в загрузки;
- кнопка **«💾 Сохранить в папку»** — отмеченные плитки перекодируются в выбранный формат
  (WebP, PNG, JPEG, BMP, TIFF — выбор рядом с кнопкой, запоминается) и сохраняются
  в папку, открытую во вкладке «Мои картинки»: первый файл — `название.ext`,
  дальше `название-1.ext`, `название-2.ext`… **Существующие файлы никогда не перезаписываются:**
  занятые имена пропускаются, и имя перепроверяется прямо перед записью — если в папке уже
  есть `название.webp` и `название-2.webp`, новые файлы получат имена `название-1.webp`
  и `название-3.webp`. Для JPEG и BMP прозрачность накладывается на белый фон,
  EXIF-поворот учитывается. Имя запрашивается при сохранении (по умолчанию — поисковый
  запрос). Если папка не открыта — программа предложит выбрать её; сохранённые файлы
  сразу появляются в просмотре.

**⬇️ Загрузки** — менеджер сохранения:
- массовое скачивание по прямым ссылкам (до 6 файлов параллельно);
- ручная вставка ссылок списком (по одной в строке);
- дедупликация ссылок в рамках сессии, отсутствие перезаписи файлов (суффиксы `-1`, `-2`…);
- имена файлов берутся из URL, расширение уточняется по `Content-Type`;
- при отказе CDN (401/403/429) загрузчик пробует запасные варианты: без Referer,
  с Referer самого сайта картинки, а для обёрток Cloudflare `/cdn-cgi/image/…` —
  прямой адрес оригинала;
- выбор папки сохранения (по умолчанию `Изображения\ImageHunter`), лимит 100 МБ на файл.

**📜 Журнал** — хроника работы (вкладка добавлена справа):
- что открывалось, что нашёл поиск, какие файлы перетаскивались мышью и чем
  закончилось перетаскивание, сколько скачано/сохранено, какие ошибки случились;
  если конкретный файл не скачался или не сохранился — в журнале будет и ссылка,
  и причина (например «не изображение (text/html)», «таймаут», «файл слишком большой»);
- ошибки выделяются красным, предупреждения — оранжевым; журнал ограничен
  5000 последними строками;
- кнопки «🧹 Очистить» и «📋 Копировать всё» — легко приложить журнал к отчёту
  об ошибке; необработанные исключения тоже попадают в журнал;
- вкладки главного окна можно перетаскивать мышью и переставлять в любом порядке.

Иконка приложения («фото с лупой») нарисована программно и встраивается в окно;
для Windows в комплекте многоразмерный `app_icon.ico`.

## Установка

### Установка одной строкой (рекомендуется)

Установщик сам спросит папку установки, создаст виртуальное окружение, скачает зависимости и создаст ярлыки.

**Windows** (PowerShell — скопируйте строку целиком):

```powershell
irm https://codeload.github.com/teliy/image-hunter/zip/refs/heads/main -OutFile "$env:TEMP\ih.zip"; Expand-Archive "$env:TEMP\ih.zip" "$env:TEMP\ih-src" -Force; powershell -NoProfile -ExecutionPolicy Bypass -File "$env:TEMP\ih-src\image-hunter-main\install.ps1"
```

> Почему так: (1) установщик сохранён с UTF-8 BOM (нужен для кириллицы при запуске файлом), а PowerShell 5.1 при `iex` ломается на BOM-символе — сбивается разбор `param()`, поэтому только запуск файлом (`-File`); (2) `raw.githubusercontent.com` кэширует файлы на 5 минут (`cache-control: max-age=300`), причём CDN игнорирует query-параметры — повторный запуск сразу после обновления репозитория может скачать старую копию. `codeload.github.com` генерирует архив на лету, без этого кэша (либо просто подождите 5 минут и повторите raw-команду).

**Linux** (bash):

```bash
curl -fsSL https://raw.githubusercontent.com/teliy/image-hunter/main/install.sh | bash
```

Что делает установщик:
- проверит Python 3.10–3.14 и при необходимости предложит установку (winget на Windows / пакетный менеджер на Linux);
- спросит, куда устанавливать (по умолчанию `%LOCALAPPDATA%\ImageHunter` / `~/.local/share/image-hunter`);
- скачает код (git не нужен), создаст `.venv`, поставит зависимости;
- создаст ярлык в меню «Пуск» (Windows) / `.desktop`-ярлык и команду `image-hunter` (Linux).

> **Alpine Linux (musl):** установщик понимает `apk` и принимает Python 3.10–3.14 (в stable это 3.12, в edge — 3.14). У PySide6 нет musl-сборок, поэтому установщик ставит `gcompat` и разрешает pip'у glibc-колёса — обычно этого достаточно, но QtWebEngine на musl может не запуститься; надёжный вариант — Docker или дистрибутив на базе glibc (Debian, Ubuntu, Fedora).

**Обновление и удаление:**

| Действие | Windows | Linux |
|---|---|---|
| Обновиться | `ImageHunter.bat update`, повторить однострочник **или прямо из программы: «Справка → Проверить обновления» / кнопка «🔄 Обновить» (Ctrl+U)** | `image-hunter update` |
| Удалить | `ImageHunter.bat uninstall` | `image-hunter uninstall` |
| Версия | `ImageHunter.bat version` | `image-hunter --version` |

> Если `ImageHunter.bat` пропал (например, обновление было прервано старой версией установщика) — восстановите его однострочником с указанием папки установки:
>
> ```powershell
> $env:IH_DIR='C:\ImageHunter'; irm https://codeload.github.com/teliy/image-hunter/zip/refs/heads/main -OutFile "$env:TEMP\ih.zip"; Remove-Item "$env:TEMP\ih-src" -Recurse -Force -ErrorAction SilentlyContinue; Expand-Archive "$env:TEMP\ih.zip" "$env:TEMP\ih-src" -Force; powershell -NoProfile -ExecutionPolicy Bypass -File "$env:TEMP\ih-src\image-hunter-main\install.ps1" -Update -AssumeYes
> ```
>
> (подставьте свою папку установки вместо `C:\ImageHunter`; `.venv` и настройки при этом сохраняются).

### Установка из приватного репозитория (с токеном)

Для **приватного** репозитория GitHub не отдаёт файлы через `raw.githubusercontent.com` без авторизации — обычный однострочник вернёт `404: Not Found` ещё до запуска установщика. Нужно скачать установщик с заголовком `Authorization` и запустить его локально.

**Windows** (PowerShell, одной строкой — подставьте свой токен):

```powershell
$t="ghp_ВАШ_ТОКЕН"; iwr https://raw.githubusercontent.com/teliy/image-hunter/main/install.ps1 -Headers @{Authorization="token $t"} -UseBasicParsing -OutFile "$env:TEMP\ih-install.ps1"; $env:IH_GH_TOKEN=$t; powershell -NoProfile -ExecutionPolicy Bypass -File "$env:TEMP\ih-install.ps1"
```

**Linux** (bash):

```bash
export IH_GH_TOKEN=ghp_ВАШ_ТОКЕН
curl -fsSL -H "Authorization: token $IH_GH_TOKEN" https://raw.githubusercontent.com/teliy/image-hunter/main/install.sh | bash
```

Токен нужен с правом чтения репозитория: classic — scope `repo`, fine-grained — «Contents: Read-only». Установщик сохранит токен в `.gh_token` внутри папки установки для будущих авто-обновлений; удалите файл, если это не нужно.
Переменные для неинтерактивной работы: `IH_ASSUME_YES=1` (все ответы «по умолчанию»), `IH_DIR=<путь>`, `IH_PYTHON=/путь/к/python` (указать интерпретатор вручную, если авто-поиск не устраивает).

### Установка вручную

Требуется Windows 10/11 и Python 3.10–3.14 (64-бит).

```bat
git clone https://github.com/teliy/image-hunter.git
cd image-hunter
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python main.py
```

## Как пользоваться

1. **Найти картинки:** вкладка «Поиск картинок» → введите запрос → выберите поисковик → «Найти».
   Или введите запрос в общее поле над вкладками — «🔎 Найти везде» откроет его во всех поисковиках сразу.
2. **Собрать ссылки:** дождитесь загрузки выдачи (можно прокрутить вниз) → «📋 Собрать ссылки». Список автоматически уйдёт на вкладку «Загрузки», скачивание начнётся сразу.
3. **Скачать вручную:** вкладка «Загрузки» → вставьте прямые ссылки на картинки → «⬇ Скачать ссылки».
4. **Посмотреть скачанное:** кнопка «Открыть» откроет папку сохранения; её же можно открыть во вкладке «Мои картинки».

## Как устроен сбор ссылок

JS-скрипт (`app/core/extractor.py`) выполняется на странице выдачи и собирает:
`img[src]`, `srcset`, data-атрибуты ленивой загрузки; раскрывает оригиналы из прокси
`external-content.duckduckgo.com/iu/?u=…`; разбирает JSON в атрибутах `data-bem` Яндекса;
сканирует сырой HTML (с раскрытием `\u002F` и `\/`) на прямые ссылки на файлы.
За один раз собирается до 500 ссылок. Страница не «взламывается» — используется только
то, что браузер и так уже загрузил и показал.

## Решение проблем

**Программа зависла на Linux (сессия Wayland).** Если плагин wayland не
загрузился (в терминале при запуске видно `Could not load the Qt platform
plugin "wayland"`), приложение работает через XWayland, и связка встроенного
браузера с видеодрайвером может зависать намертво. Начиная с v0.6.4 Image
Hunter сам замечает это при запуске и отключает GPU у встроенного браузера —
страницы рендерятся программно (на скорость поиска и скачивания картинок это
не влияет), в «Журнале» появляется поясняющая запись. Управление вручную:

- `IH_GPU=0 image-hunter` — выключить GPU принудительно;
- `IH_GPU=1 image-hunter` — оставить GPU включённым, автодетект не применять;
- `QTWEBENGINE_CHROMIUM_FLAGS="--disable-gpu" image-hunter` — то же штатным
  флагом Chromium (свои флаги перечисляются через пробел).

Если страницы во вкладках поиска остаются пустыми (Alpine/musl и другие
системы, где песочница Chromium не запускается), добавьте `--no-sandbox`:

    QTWEBENGINE_CHROMIUM_FLAGS="--no-sandbox --disable-gpu" image-hunter

**Вкладка поиска серая, а в терминале есть строка про render process** —
программа теперь сама перезапускает упавший процесс отрисовки вкладки (две
попытки), событие видно в «Журнале».

**Страница вечно «грузится», вкладка не отвечает** — с v0.7.0 загрузка
останавливается автоматически через 45 секунд, в «Журнале» будет адрес.
Если такое повторяется на всех сайтах — проверьте сеть/прокси.

**В «Журнале» запись про песочницу (sandbox)** — ядро вашей системы
запрещает пользовательские пространства имён, без них песочница Chromium
не запускается и вкладки падают по кругу (выглядит как зависание).
Программа сама запустила браузер без песочницы. Вернуть песочницу:
`IH_NO_SANDBOX=0 image-hunter`.

**В терминале ошибки вида `handshake failed … net_error -202`** — это не
зависание программы, а отказ доверять сертификатам сайтов: проверьте
правильность системных часов, антивирус/прокси с перехватом HTTPS и
наличие системных корневых сертификатов (`ca-certificates`). После
`net_error -100` (соединение закрыто) проверьте доступность сети.

**Зависает именно старая версия** — если в терминале видна ошибка
`js: Uncaught TypeError … appendChild`, у вас версия до v0.6.4: обновитесь
(`ImageHunter.bat update` / `image-hunter update` — на Linux установщик
обновляет программу той же командой установки).
