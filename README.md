# Image Hunter

[English](README.en.md) | [中文](README.zh.md) | Русский

Программа для Windows и Linux: **просмотр локальных изображений + поиск картинок в поисковиках + массовое сохранение по ссылкам** — всё в одном окне, на четырёх вкладках (четвёртая — «📜 Журнал»: хроника всей работы).

Написана на Python + PySide6 (Qt6): тяжёлые операции (рендеринг, сеть, декодирование картинок) выполняет нативный Qt, поэтому интерфейс быстрый и отзывчивый. Интерфейс доступен на **русском, английском и китайском** языках (выбор — в статус-баре, перевод применяется на лету).

> **⚡ Особый упор — быстрая работа в сети и с сетевыми дисками** (SMB/NAS, смонтированные папки, Windows-шары): папка читается одним обращением к диску, миниатюры строятся только для видимой части списка, готовые превью кэшируются на диске. Сетевая папка с тысячами фотографий открывается без «тормозов» — ни в программе, ни в сети. Подробности — в разделе [«Быстрая работа в сети и с сетевыми дисками»](#быстрая-работа-в-сети-и-с-сетевыми-дисками).

## Быстрая работа в сети и с сетевыми дисками

Image Hunter изначально писался под сценарий «фотографии лежат на сетевом диске (NAS, Windows-шара, смонтированная папка), а канал не резиновый». Обычные просмотрщики на таком сценарии «умирают»: список из 10 000 файлов — это 10 000 запросов stat по сети, а массовая прогрузка миниатюр забивает канал целиком. Ниже — что именно сделано и почему это работает.

**1. Папка читается одним проходом — без stat каждого файла.** Классический подход `os.listdir()` + `os.stat()` на каждый файл превращается в SMB-сети в две сетевые операции на файл. Image Hunter использует `os.scandir()`: тип файла, размер и время изменения приходят вместе с перечислением — вход в папку это одна сетевая операция, сколько бы файлов в ней ни было. Скрытые файлы и картинки отфильтровываются по этим же данным, без единого лишнего запроса.

**2. Ленивые миниатюры: грузится только то, что видно.** Массовая прогрузка предпросмотра отключена полностью. Миниатюры строятся только для видимой части списка (плюс запас на высоту окна); при прокрутке догружается новая порция, при обратной прокрутке ничего не перечитывается. Открыли сетевую папку — программа запросила у сети ровно те файлы, которые попали на экран (шесть из тысячи в типовом окне). Кнопка-выключатель «🖼 Миниатюры» отключает предпросмотр совсем — состояние запоминается между запусками.

**3. Дисковый кэш миниатюр — повторное открытие мгновенно.** Каждая готовая миниатюра пишется в `%LOCALAPPDATA%\ImageHunter\thumbs` (Linux: `~/.cache/ImageHunter/thumbs`). Ключ — SHA-1 от «путь + размер + mtime»: изменился файл — кэш сам устареет, обслуживать его не нужно. Повторное открытие той же сетевой папки отрисовывается из локального кэша и не делает ни одного обращения к сети за картинками. Лимит кэша 256 МБ, запись атомарная (через временный файл) — обрыв связи не оставит битых миниатюр.

**4. Поколения задач: ушёл из папки — лишнее молча отбрасывается.** Каждому сканированию присваивается номер-«поколение». Миниатюры и результаты поиска прошлой папки, пришедшие с опозданием, отбрасываются: очередь задач не копится, сеть не гоняет уже ненужное.

**5. Поиск по подпапкам — в фоне, без блокировки окна.** Поиск по имени идёт в фоновом потоке тем же «однопроходным» scandir и отдаёт результаты по мере обхода: окно остаётся отзывчивым, сеть нагружается равномерно, миниатюры при поиске не читаются.

**6. Интерфейс — настроил один раз.** Ширина дерева папок и ленты миниатюр запоминается между запусками; иконки отдаются в список батчами — сотни новых строк не вызывают лавину перерисовок.

**7. Сеть в загрузках — быстро, но вежливо.** Скачивание — до 6 файлов параллельно в QThreadPool, стриминговая запись чанками по 64 КБ (файл не копится в памяти), таймауты 10/60 с, лимит 100 МБ на файл. WebP-сохранение работает в 3 потока — щадяще к сайтам-источникам.

**8. Обновление в обход кэша CDN.** Установщик и проверка обновлений качают код через `codeload.github.com`, который генерирует архив на лету: новая версия доступна сразу после пуша, без 5-минутного кэша `raw.githubusercontent.com`.

## Возможности

**📁 Мои картинки** — локальный просмотрщик:
- **дерево дисков и папок слева**: смонтированные диски и устройства (со свободным местом в подсказке),
  быстрые ссылки «Домой» и «Изображения»; папки раскрываются лениво, клик по папке — сразу показать её картинки;
  ширина панели регулируется мышью; кнопка «⟳» обновляет список дисков (после подключения флешки);
- **быстрый поиск папок**: поле «🔍 Поиск папки…» над деревом находит папку по части имени — внутри папки,
  выбранной в дереве (на любой глубине); пока ничего не выбрано — в Домой, Изображениях и на всех дисках;
  область поиска показывается над деревом и пишется в журнал; совпадения появляются в дереве прямо в процессе
  фонового обхода (имя + путь родителя серым), клик открывает папку, Enter — первую найденную, Esc — сброс;
  регистр не важен, скрытые папки не сканируются, выдача и время обхода ограничены, поэтому даже огромный диск
  не подвесит окно;
- **ленивые миниатюры**: грузятся только для видимой части списка (при прокрутке догружаются
  остальные) — вход в сетевую папку с тысячами фотографий больше не читает все файлы подряд
  и не забивает сеть; кнопка-выключатель «🖼 Миниатюры» полностью отключает предпросмотр
  (состояние запоминается между запусками); миниатюры кэшируются на диске
  (`%LOCALAPPDATA%\ImageHunter\thumbs` / `~/.cache/ImageHunter/thumbs`), поэтому повторное
  открытие папки — в том числе сетевой — почти мгновенное; папки сканируются одним проходом,
  без «стата» каждого файла (быстро даже по SMB-диску);
- **выделение и drag'n'drop**: выделите картинки в ленте (Ctrl/Shift — как в Проводнике)
  и перетащите их мышью в Проводник, почту или другое приложение — передаются
  оригинальные файлы (`text/uri-list`); запуск перетаскивания подстрахован тремя
  независимыми путями (фильтр событий, собственный перехват движения мыши, встроенная
  механика Qt), а каждый шаг пишется в «Журнал»; **если тянуть не получается —
  запасной путь без драга:** `Ctrl+C` (или правый клик → «Копировать выделенные файлы»),
  затем вставьте их куда нужно — `Ctrl+V` в Проводник или браузер;
- **поиск по имени файла**: введите часть имени в поле сверху — найдутся все картинки
  в текущей папке и всех подпапках; без масок и `*`, регистр не важен, результаты
  появляются сразу в процессе обхода; поле можно расширить мышкой — потяните за его
  левый или правый край (курсор превратится в «↔»), ширина запомнится между запусками;
  чекбокс **«игнорировать дефис»**: поиск не различает дефисы — запрос «23542-23523»
  найдёт и «2354223523», и «23542-23523» (артикулы запчастей пишут то с дефисом,
  то без, и не всегда на том же месте); состояние чекбокса запоминается;
- **удаление файлов**: клавиша `Delete` или правый клик → «🗑 Удалить» —
  выделенные картинки перемещаются в корзину (восстановимо из Проводника); подтверждение
  с числом файлов, каждая неудача — с причиной в журнале. На дисках без корзины
  (сетевые, часть съёмных) программа предлагает удалить окончательно — с отдельным
  подтверждением;
- при запуске автоматически открывается последняя папка (если в ней до 2000 картинок)
  и восстанавливается последний запрос поиска — как перед закрытием;
- полноэкранный просмотр, зум (`+` / `−` / `Ctrl+колесо`), «вписать в окно», «100%»;
- навигация стрелками ←/→, сортировка «по-человечески» (file2 < file10);
- **поддержка AVIF**: файлы `.avif` видны в ленте с миниатюрами и полноэкранным просмотром,
  а AVIF-картинки, скачанные по ссылкам (маркетплейсы отдают AVIF даже под именем `.jpg`),
  перекодируются в любой из форматов; декодер — Pillow + pillow-avif-plugin (ставится автоматически);
- просмотр выбранной картинки грузится в фоновом потоке — выбор файла на сетевом диске
  (как и чтение тяжёлого AVIF) больше не подвешивает окно («Не отвечает»);
- анимированные GIF, поддержка JPG/PNG/WEBP/BMP/GIF/AVIF;
- двойной клик по миниатюре — открыть файл системным просмотрщиком; кнопка «Показать в проводнике»;
- лента миниатюр растягивается мышью за разделитель (ширина панелей запоминается между запусками),
  поле поиска находится справа на панели инструментов и тоже меняет ширину мышью — за левый/правый край.

**🌐 Поиск картинок** — встроенный браузер (Chromium):
- **мультивкладки «как в браузере»**: «＋»/Ctrl+T — ещё одна вкладка поиска, у каждой свои
  поисковик и браузер; правый клик по вкладке — дублировать / закрыть / закрыть другие /
  закрыть справа; крестик закрывает вкладку (последнюю заменяет свежая), вкладки
  перетаскиваются мышью; заголовок вкладки — выбранный поисковик, а кружок — его
  фирменный цвет (Яндекс — красный, DuckDuckGo — оранжевый, Google — синий,
  Bing — зелёный); открытые вкладки восстанавливаются при следующем запуске;
- **одно поле — все поисковики**: общая строка запроса над вкладками; Enter или
  **«🔎 Найти везде»** — запрос открывается сразу во всех 13 поисковиках,
  у каждого своя вкладка с выдачей (уже открытые вкладки обновятся);
- поисковики (13): Яндекс.Картинки, Google, Bing, DuckDuckGo (безопасный режим),
  Brave, Yahoo, Ecosia, Startpage, Mojeek, Baidu, Sogou, Naver, Mail.ru;
- капчу Яндекса можно вводить прямо во встроенном браузере;
- **чекбоксы на плитках выдачи**: отметьте оранжевыми галочками нужные картинки —
  на кнопке появится счётчик, а по **«Скачать отмеченные»** скачаются большие оригиналы
  (у Яндекса берётся `origUrl` — тот же файл, что открывается при клике на превью,
  например `avatars.mds.yandex.net/get-mpic/…/orig`; для остальных поисковиков —
  оригинал из параметров ссылок плиток);
- чекбоксы работают на актуальной разметке DuckDuckGo (2025): плитки без привычных
  классов, а «оригиналы» — из кеша Bing без расширения в имени файла — распознаются
  и отмечаются;
- чекбоксы работают и на актуальной выдаче Google (udm=2): миниатюры
  `encrypted-tbn0.gstatic.com`/`googleusercontent` без расширения распознаются,
  ленивые плитки (картинка подгружается позже отрисовки) получают галочку,
  а непрерывная перерисовка выдачи больше не откладывает появление чекбоксов;
- чекбоксы подхватывают плитки, догружаемые при прокрутке выдачи;
- кнопка **«✕ Снять отметки»** — снимает все оранжевые галочки с плиток одним нажатием
  (активна, когда есть хоть одна отметка);
- кнопка **«Собрать ссылки»** — как раньше: все картинки открытой страницы (миниатюры, оригиналы
  из прокси DuckDuckGo, из `data-bem`/`data-state` JSON Яндекса) одной пачкой в загрузки;
- кнопка **«💾 Сохранить в папку»** — отмеченные плитки перекодируются в выбранный формат
  (WebP, PNG, JPEG, BMP, TIFF — выбор рядом с кнопкой, запоминается) и сохраняются
  в папку, открытую во вкладке «Мои картинки»: первый файл — `название.ext`,
  дальше `название-1.ext`, `название-2.ext`… **Существующие файлы никогда не перезаписываются:**
  занятые имена пропускаются, и имя перепроверяется прямо перед записью — если в папке уже
  есть `название.webp` и `название-2.webp`, новые файлы получат имена `название-1.webp`
  и `название-3.webp`. Для JPEG и BMP прозрачность накладывается на белый фон,
  EXIF-поворот учитывается. Имя запрашивается при сохранении (по умолчанию — поисковый
  запрос). Если папка не открыта — программа предложит выбрать её; сохранённые файлы
  сразу появляются в просмотре.

**⬇️ Загрузки** — менеджер сохранения:
- массовое скачивание по прямым ссылкам (до 6 файлов параллельно);
- ручная вставка ссылок списком (по одной в строке);
- дедупликация ссылок в рамках сессии, отсутствие перезаписи файлов (суффиксы `-1`, `-2`…);
- имена файлов берутся из URL, расширение уточняется по `Content-Type`;
- при отказе CDN (401/403/429) загрузчик пробует запасные варианты: без Referer,
  с Referer самого сайта картинки, а для обёрток Cloudflare `/cdn-cgi/image/…` —
  прямой адрес оригинала;
- выбор папки сохранения (по умолчанию `Изображения\ImageHunter`), лимит 100 МБ на файл.

**📜 Журнал** — хроника работы (вкладка добавлена справа):
- что открывалось, что нашёл поиск, какие файлы перетаскивались мышью и чем
  закончилось перетаскивание, сколько скачано/сохранено, какие ошибки случились;
  если конкретный файл не скачался или не сохранился — в журнале будет и ссылка,
  и причина (например «не изображение (text/html)», «таймаут», «файл слишком большой»);
- ошибки выделяются красным, предупреждения — оранжевым; журнал ограничен
  5000 последними строками;
- кнопки «🧹 Очистить» и «📋 Копировать всё» — легко приложить журнал к отчёту
  об ошибке; необработанные исключения тоже попадают в журнал;
- вкладки главного окна можно перетаскивать мышью и переставлять в любом порядке.

Иконка приложения («фото с лупой») нарисована программно и встраивается в окно;
для Windows в комплекте многоразмерный `app_icon.ico`.

## Установка

### Установка одной строкой (рекомендуется)

Установщик сам спросит папку установки, создаст виртуальное окружение, скачает зависимости и создаст ярлыки.

**Windows** (PowerShell — скопируйте строку целиком):

```powershell
irm https://codeload.github.com/teliy/image-hunter/zip/refs/heads/main -OutFile "$env:TEMP\ih.zip"; Expand-Archive "$env:TEMP\ih.zip" "$env:TEMP\ih-src" -Force; powershell -NoProfile -ExecutionPolicy Bypass -File "$env:TEMP\ih-src\image-hunter-main\install.ps1"
```

> Почему так: (1) установщик сохранён с UTF-8 BOM (нужен для кириллицы при запуске файлом), а PowerShell 5.1 при `iex` ломается на BOM-символе — сбивается разбор `param()`, поэтому только запуск файлом (`-File`); (2) `raw.githubusercontent.com` кэширует файлы на 5 минут (`cache-control: max-age=300`), причём CDN игнорирует query-параметры — повторный запуск сразу после обновления репозитория может скачать старую копию. `codeload.github.com` генерирует архив на лету, без этого кэша (либо просто подождите 5 минут и повторите raw-команду).

**Linux** (bash):

```bash
curl -fsSL https://raw.githubusercontent.com/teliy/image-hunter/main/install.sh | bash
```

Что делает установщик:
- проверит Python 3.10–3.13 и при необходимости предложит установку (winget на Windows / пакетный менеджер на Linux);
- спросит, куда устанавливать (по умолчанию `%LOCALAPPDATA%\ImageHunter` / `~/.local/share/image-hunter`);
- скачает код (git не нужен), создаст `.venv`, поставит зависимости;
- создаст ярлык в меню «Пуск» (Windows) / `.desktop`-ярлык и команду `image-hunter` (Linux).

**Обновление и удаление:**

| Действие | Windows | Linux |
|---|---|---|
| Обновиться | `ImageHunter.bat update`, повторить однострочник **или прямо из программы: «Справка → Проверить обновления» / кнопка «🔄 Обновить» (Ctrl+U)** | `image-hunter update` |
| Удалить | `ImageHunter.bat uninstall` | `image-hunter uninstall` |
| Версия | `ImageHunter.bat version` | `image-hunter --version` |

> Если `ImageHunter.bat` пропал (например, обновление было прервано старой версией установщика) — восстановите его однострочником с указанием папки установки:
>
> ```powershell
> $env:IH_DIR='C:\ImageHunter'; irm https://codeload.github.com/teliy/image-hunter/zip/refs/heads/main -OutFile "$env:TEMP\ih.zip"; Remove-Item "$env:TEMP\ih-src" -Recurse -Force -ErrorAction SilentlyContinue; Expand-Archive "$env:TEMP\ih.zip" "$env:TEMP\ih-src" -Force; powershell -NoProfile -ExecutionPolicy Bypass -File "$env:TEMP\ih-src\image-hunter-main\install.ps1" -Update -AssumeYes
> ```
>
> (подставьте свою папку установки вместо `C:\ImageHunter`; `.venv` и настройки при этом сохраняются).

### Установка из приватного репозитория (с токеном)

Для **приватного** репозитория GitHub не отдаёт файлы через `raw.githubusercontent.com` без авторизации — обычный однострочник вернёт `404: Not Found` ещё до запуска установщика. Нужно скачать установщик с заголовком `Authorization` и запустить его локально.

**Windows** (PowerShell, одной строкой — подставьте свой токен):

```powershell
$t="ghp_ВАШ_ТОКЕН"; iwr https://raw.githubusercontent.com/teliy/image-hunter/main/install.ps1 -Headers @{Authorization="token $t"} -UseBasicParsing -OutFile "$env:TEMP\ih-install.ps1"; $env:IH_GH_TOKEN=$t; powershell -NoProfile -ExecutionPolicy Bypass -File "$env:TEMP\ih-install.ps1"
```

**Linux** (bash):

```bash
export IH_GH_TOKEN=ghp_ВАШ_ТОКЕН
curl -fsSL -H "Authorization: token $IH_GH_TOKEN" https://raw.githubusercontent.com/teliy/image-hunter/main/install.sh | bash
```

Токен нужен с правом чтения репозитория: classic — scope `repo`, fine-grained — «Contents: Read-only». Установщик сохранит токен в `.gh_token` внутри папки установки для будущих авто-обновлений; удалите файл, если это не нужно.
Переменные для неинтерактивной работы: `IH_ASSUME_YES=1` (все ответы «по умолчанию»), `IH_DIR=<путь>`.

### Установка вручную

Требуется Windows 10/11 и Python 3.10–3.13 (64-бит).

```bat
git clone https://github.com/teliy/image-hunter.git
cd image-hunter
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python main.py
```

## Как пользоваться

1. **Найти картинки:** вкладка «Поиск картинок» → введите запрос → выберите поисковик → «Найти».
   Или введите запрос в общее поле над вкладками — «🔎 Найти везде» откроет его во всех поисковиках сразу.
2. **Собрать ссылки:** дождитесь загрузки выдачи (можно прокрутить вниз) → «📋 Собрать ссылки». Список автоматически уйдёт на вкладку «Загрузки», скачивание начнётся сразу.
3. **Скачать вручную:** вкладка «Загрузки» → вставьте прямые ссылки на картинки → «⬇ Скачать ссылки».
4. **Посмотреть скачанное:** кнопка «Открыть» откроет папку сохранения; её же можно открыть во вкладке «Мои картинки».

```
    │   ├── updates.py         # проверка обновлений и запуск установщика из GUI

        └── downloads.py       # таблица загрузок
```

## Как устроен сбор ссылок

JS-скрипт (`app/core/extractor.py`) выполняется на странице выдачи и собирает:
`img[src]`, `srcset`, data-атрибуты ленивой загрузки; раскрывает оригиналы из прокси
`external-content.duckduckgo.com/iu/?u=…`; разбирает JSON в атрибутах `data-bem` Яндекса;
сканирует сырой HTML (с раскрытием `\u002F` и `\/`) на прямые ссылки на файлы.
За один раз собирается до 500 ссылок. Страница не «взламывается» — используется только
то, что браузер и так уже загрузил и показал.
