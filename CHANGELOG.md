# Журнал изменений Image Hunter

Все заметные изменения программы, новые версии сверху. Установка — в [README](README.md).

## 0.8.5 — 2026-11-09

**Перетаскивание выделенных файлов в папки дерева.** Пожелание: «нужно сделать изменение — нужно чтобы выделенные файлы могли переноситься мышкой в любую папку в дереве директорий».

- **Drop на узел дерева.** Выделите картинки в ленте (Ctrl/Shift — как в Проводнике), зажмите плитку и ведите к дереву слева: папка под курсором подсвечивается полупрозрачным цветом выделения, свёрнутая папка сама раскрывается после паузы (800 мс — как в Проводнике), отпускание кнопки — перенос. Бросать можно и на диски (перенос в корень диска), и на избранные папки; принимаются и файлы из Проводника — любые `file://`-url'ы, так что из окон тоже можно тянуть в дерево программы.
- **Фоновый перенос без затираний.** Перемещение выполняет новый `_MoveTask` в рабочем потоке: `shutil.move` по сети может подвиснуть на сетевой тайм-аут — GUI-поток не ждёт (принцип v0.7.2), между дисками `shutil.move` сам копирует и удаляет. Файлы, уже лежащие в целевой папке, пропускаются ещё до старта (по каталогам — без обращений к диску в GUI-потоке); при конфликте имён файл получает свободное имя («cat-1.png») — ничего не затирается. Итог — в статусе («Перемещено: N → папка»; с ошибками — сколько не удалось) и в «Журнале»: начало с именами файлов, завершение с числом пропущенных, каждая ошибка — с причиной.
- **Лента честно худеет.** Уехавшие файлы убираются из ленты; кэши по номерам строк чистятся тем же кодом, что после удаления, — теперь это общий метод `_list_rows_changed` (дубликат после rembg-возврата тоже ушёл). При активном поиске по имени результаты пересобираются — уехавшие файлы не числятся найденными. Пока перенос едет, новый drop не множится: статус честно скажет «Предыдущее перемещение ещё идёт».
- **Механика.** Новый класс `_Tree` (QTreeWidget, DragDropMode.DropOnly, свои dragEnterEvent/dragMoveEvent/dragLeaveEvent/dropEvent): штатный style-индикатор QTreeWidget рисуется только для своих mime-моделей, поэтому цель показываем подсветкой узла (полупрозрачный цвет выделения, снимается при уходе/отпуске). Пути берутся из mime (`text/uri-list`) — как у внешнего драга, ничего не запоминается в сторонах. Подсказка дерева «Перетащите выделенные в ленте файлы…» локализована ru/en/zh и перетранслируется при смене языка.
- Тесты: новый `scripts/test_tree_drop.py` — 31 проверка (режимы и подсказка дерева; drag с файлами принят, без url'ов и на пустом месте — отклонён; подсветка цели, её переезд и снятие; авто-раскрытие по паузе; drop с реальным переносом на диск; лента худеет; журнал — начало с именами и итог; конфликт имён → `pic_1-1.png`; «файлы уже в этой папке»; второй drop во время переноса не множится; несуществующий файл — честная ошибка в статусе и журнале; drop на пустое место и без url'ов ничего не меняет; локализация ru/en/zh); смоуки — версия 0.8.5; весь набор тестов зелёный (два webengine-смоука в headless-песочнице без GPU не стартуют и на коде до изменения — среда, не код); README×3, CHANGELOG, RELEASE_NOTES.

## 0.8.4 — 2026-11-08

**Разрешение картинки в подписи плитки «Моих картинок».** Пожелание: «во вкладке "Мои картинки", в блоке со списком файлов, под маленькими изображениями — не только имя файла, но и разрешение картинки».

- **Подпись плитки — в две строки.** Под именем файла серым шрифтом на шаг меньше выводится исходное разрешение («1920×1080») — тем же форматом, каким размер показывает полноэкранный просмотр; длинное имя по-прежнему сокращается многоточием, разрешение — под ним. Место под вторую строку резервируется сразу, поэтому лента не «прыгает», когда разрешение доезжает; плитки без миниатюр (выключатель «🖼 Миниатюры», нечитаемый файл) рисуются с одной строкой.
- **Разрешение — из заголовка, а не из миниатюры.** Из уменьшенной миниатюры 160×90 исходный размер не восстановить (1920×1080 и 1280×720 выглядят одинаково), поэтому `imgload` получил `load_file_ex()`/`load_bytes_ex()`: исходные ширина и высота берутся из заголовка (`QImageReader.size()` ещё до декодирования, уже с учётом EXIF-поворота; для AVIF — из Pillow) попутно, второй раз файл не читается. Прежние `load_file()`/`load_bytes()` работают как раньше — `test_network_freeze` и `test_avif` прошли без правок.
- **Разрешение переживает кэш миниатюр.** Исходный размер хранится прямо внутри кэшированного PNG (tEXt-чанк `ih-dims`): при попадании в кэш оригинал не читается вовсе — сетевые папки не дёргаются, а подпись всё равно с разрешением. Ключ кэша получил версию v2: после обновления кэш один раз перекодируется, чтобы разрешение появилось и у давно открытых папок; записи до v2 — самые старые, их первой дочищает `_prune_thumb_cache`.
- **Механика.** Новый делегат ленты `_ThumbDelegate` рисует плитку сам: фон, выделение, фокус и прямоугольники иконки/подписи берутся у стиля (QStyle.SubElement) — раскладка совпадает со штатным делегатом, добавлена только вторая строка. Разрешение живёт в отдельной роли плитки (`Qt.UserRole + 10`): текст плитки остаётся чистым именем файла, поэтому переименование (F2, двойной клик по имени, редактор с выделением имени без расширения), поиск по имени, удаление/восстановление и drag'n'drop не затронуты — редактор, как и раньше, получает только имя. Очистки ленты (смена папки, поиск, удаление, rembg-возврат, выключатель миниатюр) чистят и очередь разрешений.
- Тесты: новый `scripts/test_thumb_caption.py` — 24 проверки (парсер чанка, `load_file_ex` на PNG/JPEG/мусоре, совместимость `load_bytes`, разрешение приходит и с декода, и из кэша, текст плитки остаётся именем, `sizeHint` с запасом под вторую строку, редактор переименования без разрешения, отрисовка делегата без ошибок с ролью и без); смоуки — версия 0.8.4.

## 0.8.3 — 2026-11-05

**Поиск с телефона: пять поисковиков вместо двух, мост из программы и журнал сервера.** Пожелание: «DuckDuckGo ничего не находит, Bing ищет бесконечно. Другие поисковики можно добавить? Или можно передавать данные из самой программы? Очищенные и облегченные? Нужно чтобы в журнале отображалась деятельность в web-сервере и в API».

- **Новые движки** в шапке режима «Интернет» (выбор запоминается, по умолчанию — Openverse): **Openverse** — официальный JSON-API агрегатора открытых картинок (Flickr, Wikimedia, NASA и сотни источников; без ключа, без скрапинга, готовые миниатюры, повтор при разовом сбое API), **Wikimedia** — официальный MediaWiki API Commons (миниатюры нужного размера, честный User-Agent по политике WMF, порядок выдачи по «index»). У движков запрос жёстко ограничен по времени, у интерфейса — таймаут 60 с с тостом: вечного «Ищу…» больше не будет.
- **«Программа» — мост с вкладки «Поиск картинок».** Программа ищет настоящим браузером (QWebEngineView), которому не страшны ни блокировки DuckDuckGo, ни капчи, ни смена серверных форматов; после каждой загрузки выдачи вкладка автоматически передаёт телефону «очищенные и облегчённые» плитки (новый `collect_tiles` в `app/core/extractor.py`: оригинал из ссылок-плиток — imgurl= у Google, img_url= у Яндекса, u= у DuckDuckGo, murl из m=/data-m= у Bing; иконки и логотипы отсекаются по размеру) в новый потокобезопасный мост `app/server/desktop_results.py`; поисковик «Программа» отдаёт их через тот же `/api/web/search` (движок desktop) с пометкой источника в статусе. Хранится последняя выдача (до 200 плиток), пустой сбор ничего не затирает.
- **DuckDuckGo и Bing — честные ошибки.** Сообщение о недоступности DDG теперь прямо говорит, что сайт может быть заблокирован в вашей сети; vqd-токен ищется и в JSON-форме ("vqd":"4-…"), и в классических vqd="4-…". Bing умеет новый формат плиток data-m=, а пустую JS-оболочку без результатов отвечает ошибкой 502 с подсказкой сменить поисковик — вместо тихого пустого результата.
- **Деятельность веб-сервера и API — в «Журнале» программы.** Открытие веб-интерфейса (адрес клиента), поиск с телефона (движок, запрос, сколько нашлось; отдельно — ошибки), переименование (старое → новое), удаление (сколько и что), запуск удаления фона (сколько, модель), скачивание на устройство (имя файла), отказы в режиме «только просмотр» (какая операция) — новые ключи i18n ru/en/zh (log.event.srv_*). Миниатюры, листинги и ping в журнал не пишутся.
- Интерфейс телефона: подсказка для поисковика «Программа» («здесь появится последняя выдача…»), кнопка «Ещё» у него спрятана (выдача приходит целиком), синтаксис страницы проверен node --check, сбор плиток проверен в реальном браузере на макете выдачи.

Тесты: `scripts/test_server.py` дополнен — моки Openverse/Wikimedia (JSON-разбор, пагинация), Bing data-m= и пустая оболочка (502), vqd в JSON-форме, мост «программа → телефон» (чистка, дедуп, движок desktop, source_engine), события журнала (подключение/поиск/переименование/отказ «только просмотр»), новые элементы интерфейса; вся проверка моста в реальном браузере — макет выдачи с плитками Bing/Google/Яндекс/DDG/ленивыми превью; test_rename — детерминированная проверка статуса конфликта через наблюдение сигнала done (фоновая загрузка миниатюры могла перекрыть статус в той же пачке событий); смоуки — версия 0.8.3, README×3, CHANGELOG, RELEASE_NOTES

## 0.8.1 — 2026-11-04

**Веб-сервер: поиск и скачивание картинок из интернета — как во вкладке «Поиск картинок», только с телефона.** В мобильном интерфейсе появилась кнопка **🔎** («Интернет»): запрос уходит поисковику, плитки выдачи показываются той же лентой, отмеченные скачиваются в папку на компьютере или на само устройство.

- **Поисковики без браузера.** Во вкладке «Поиск картинок» выдача открывается встроенным Chromium, а ссылки собирает JavaScript на странице — серверу (поток программы или headless-процесс) такой путь не подходит. Поэтому сервер сам ходит по адресам с чистыми данными: **DuckDuckGo** (JSON-выдача `i.js`, токен vqd снимается со страницы выдачи) и **Bing** (серверный HTML: у каждой плитки атрибут `m=` со ссылкой на оригинал, миниатюрой и размерами). Новый файл `app/server/websearch.py` — без Qt; адреса движков — константы уровня модуля, тесты подменяют их локальным моком и проверяют разбор без сети.
- **С телефона:** плитки выдачи — та же лента (заголовок, размеры, миниатюра с CDN поисковика; если CDN не отдал — повтор через сервер); клик — полный просмотр оригинала через сервер (сайты с проверкой Referer напрямую чужие страницы не пускают); «⬇️ Скачать» сохраняет оригинал на устройство; «💾 В папку» — в папку, открытую в режиме «Файлы» (выбор помнится между заходами). Кнопка «Ещё» догружает следующую пачку (offset).
- **Отметки как в программе:** «+» на плитке — аналог чекбоксов выдачи; плавающая кнопка «⬇ N» скачивает отмеченные одним заданием (дедупликация ссылок, до 40 за раз), прогресс и итог — в статусе и тосте, каждая строка — в журнале.
- **Скачивание по правилам программы:** та же лестница попыток с Referer (часть CDN пускает только «свои» запросы), раскрытие обёртки Cloudflare `/cdn-cgi/image/`, имя из адреса ответа с подменой расширения по Content-Type (`noext` без расширения станет `noext.png`), атомарно-свободное имя (`cat-1.png`) без затираний, лимит 100 МБ на файл.
- **API:** `GET /api/web/search` (engine, q, offset), `GET /api/web/proxy` (url, `dl=1` — attachment), `POST /api/web/download` (urls, folder → фоновое задание), `GET /api/job/status?id=` — общий статус заданий rembg и скачивания. Коды честные: 400 — пустой запрос/неизвестный движок/плохая схема/папка вне корней; 403 — режим «только просмотр» (поиск — чтение и остаётся доступен, сохранение в папку — нет); 502 — поисковик или сайт с картинкой не ответил.
- Механика: `websearch.py` (поиск, `fetch_image` с лестницей, правила имён — копии правил `downloader.py`, чтобы пакет не тянул PySide6); `api.py` — web_search/web_proxy/web_download_start, общий механизм заданий `_job_start` (kind: rembg/webdl) и `job_status`; `httpd.py` — маршруты и WebSearchError → 502; `webui.py` — переключатель «Файлы/Интернет» (запоминается), выбор движка, отметки, плавающая кнопка, просмотр через прокси, RU/EN; i18n ru/en/zh — 3 новых ключа журнала (webdl_start/webdl/webdl_err). Тесты: `scripts/test_server.py` — 113 проверок; новая секция интернет-поиска на локальном мок-сервере (страница DDG с vqd, JSON i.js, HTML Bing с `m=`, картинки PNG/JPEG/не-картинка/403/404): разбор плиток (дедуп, схемы, html-сущности), offset, прокси (attachment, 400/502), фоновое скачивание (файлы на диске, `cat-1.png`, ошибки с причинами), view_only/restrict, элементы UI; смоуки — версия 0.8.1, весь набор тестов зелёный, README×3.

## 0.8.0 — 2026-11-04

**Веб-сервер: управление программой с телефона.** Новый подключаемый и полностью удаляемый модуль (`app/server/`): кнопка **🌐** в статус-баре поднимает маленький HTTP-сервер, телефон в той же сети открывает адрес (QR-код в окне модуля) и получает мобильный веб-интерфейс с почти всей функциональностью программы.

- **С телефона доступно:** лента папок с миниатюрами (общий с программой дисковый кэш миниатюр), поиск по имени (вглубь подпапок, «игнорировать дефис», предел результатов), полный просмотр со свайпами и клавишами, переименование, удаление в корзину и окончательно, удаление фона rembg фоновым заданием с опросом прогресса, диски и избранные папки, хвост журнала.
- **Внутреннее API** (`app/server/api.py`) — чистые операции над файловой системой без Qt-виджетов: те же правила переименования, что по F2 в программе; тот же формат «X_nobg.png» у rembg; однопроходный scandir-поиск.
- **Безопасность:** обязательный токен (ссылка с токеном → cookie запоминается), режим «только просмотр», ограничение корней; сравнение токена постоянным временем; страница интерфейса и API не отдают ничего без токена.

- **QR-код** в окне модуля рисует библиотека qrcode — ставится кнопкой прямо из окна (как rembg), без неё адрес показывается текстом.
