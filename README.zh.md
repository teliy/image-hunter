# Image Hunter

本地图片浏览 **+ 搜索引擎图片搜索 + 按链接批量保存** — 全部集中在一个窗口的四个标签页中（第四个是“📜 日志”：程序运行记录）。支持 Windows 和 Linux。

使用 Python + PySide6 (Qt6) 编写：繁重操作（渲染、网络、图片解码）由原生 Qt 完成，因此界面快速流畅。

> **⚡ 特别优化 — 网络及网络磁盘（SMB/NAS、挂载的共享文件夹）的快速工作**：文件夹一次请求即读完，缩略图仅为列表可见部分生成，已生成的预览缓存到磁盘。即使文件夹中有数千张照片，也不会卡顿 — 程序不卡，网络也不堵。详见[“网络及网络磁盘的快速工作”](#网络及网络磁盘的快速工作)。

## 网络及网络磁盘的快速工作

Image Hunter 从第一天起就是为“照片存放在网络磁盘（NAS、Windows 共享、挂载文件夹）而带宽有限”的场景设计的。普通看图软件在这种场景下会卡死：列出 10000 个文件意味着 10000 次网络 stat 调用，批量加载缩略图更会占满带宽。下面说明具体做了什么以及为什么有效。

**1. 文件夹一次遍历读完 — 不逐文件 stat。** 经典的 `os.listdir()` + 逐文件 `os.stat()` 在 SMB 网络中意味着每个文件两次网络操作。Image Hunter 使用 `os.scandir()`：文件类型、大小和修改时间随目录枚举一起返回 — 无论文件夹中有多少文件，打开它只需一次网络操作。隐藏文件和图片的筛选也基于同一批数据，不产生任何额外请求。

**2. 懒加载缩略图：只加载看得见的部分。** 完全禁用了批量预览加载。缩略图仅为列表可见部分（外加一屏余量）生成；向下滚动时加载新的一批，向上滚动时不会重复读取。打开网络文件夹时，程序只请求屏幕上实际显示的文件（典型窗口中一千张里只取六张）。“🖼 缩略图”开关可完全关闭预览 — 状态会在多次运行之间保留。

**3. 磁盘缩略图缓存 — 再次打开瞬间完成。** 每张生成好的缩略图写入 `%LOCALAPPDATA%\ImageHunter\thumbs`（Linux：`~/.cache/ImageHunter/thumbs`）。键为“路径 + 大小 + mtime”的 SHA-1：文件一变化，对应缓存自动失效。再次打开同一个网络文件夹时直接从本地缓存渲染，为获取图片不会发起任何网络请求。缓存上限 256 MB，写入是原子性的（通过临时文件）— 网络中断也不会留下损坏的缩略图。

**4. 任务世代：离开文件夹 — 过期任务静默丢弃。** 每次扫描都分配世代编号。迟到的旧文件夹缩略图和搜索结果会被丢弃：任务队列不会堆积，网络不会传输已无用的数据。

**5. 子文件夹搜索 — 后台运行，不阻塞窗口。** 按文件名搜索在后台线程中以同样的“一次遍历” scandir 进行，边扫描边返回结果：窗口保持响应，网络负载均匀，搜索期间不读取缩略图。

**6. 界面 — 设置一次即可。** 文件夹树和缩略图条的宽度在多次运行之间保留；图标分批交给列表 — 数百个新行不会引发重绘风暴。

**7. 下载中的网络 — 快速而有分寸。** 下载通过 QThreadPool 最多并行 6 个文件，以 64 KB 块流式写入磁盘（文件不会整个占用内存），超时 10/60 秒，单文件上限 100 MB。保存使用 3 个线程 — 对来源网站更友好。

**8. 更新绕过 CDN 缓存。** 安装程序和更新检查通过 `codeload.github.com` 获取代码，该服务实时生成压缩包：推送后新版本立即可用，不受 `raw.githubusercontent.com` 5 分钟缓存的影响。

## 秒开启动与防卡死（v0.7.0）

Image Hunter 中最重、最容易引起卡死的，是搜索标签页的内嵌浏览器：每个 QWebEngineView 都是一个完整的 Chromium 进程。从 v0.7.0 起架构改为模块化 + 惰性加载——重的东西只在真正需要时才启动：

**1. 程序启动时零 Chromium。** 以前每个搜索标签页在启动时就创建浏览器并打开起始页：恢复 11 个标签页 = 11 个 Chromium 进程 + 11 个同时进行的页面加载——在弱机或慢网上看起来就像卡死。现在启动时标签页只是它的工具栏（几千字节的界面）。标签页的浏览器在第一次显示该标签页时（`showEvent`）才创建。只要您没打开“图片搜索”标签页，Chromium 完全不会启动——窗口瞬间出现。

**2. “全局搜索”不再有加载风暴。** 一次在所有搜索引擎中搜索不再同时发起十几个加载：没有浏览器的标签页只会记住请求（pending），等您打开该标签页时才执行。网络、内存和 CPU 只花在您正在看的内容上；您从未打开的标签页一个字节也没花。

**3. WebEngine 的全部配置集中在一个模块。** `app/core/webengine.py` 是唯一入口：平台插件警告捕获（损坏的 Wayland）、`--disable-gpu`（自动检测，IH_GPU）、`--disable-dev-shm-usage`（在 /dev/shm 极小的系统上标签页会静默崩溃并循环重启）、`--disable-breakpad`，以及 `--no-sandbox`——仅当内核禁止用户命名空间时（否则标签页会循环崩溃、看起来像卡死；切换会写入“日志”，如需恢复沙箱请设 `IH_NO_SANDBOX=0`）。

**4. “永久加载”看门狗。** 45 秒内没有打开的页面（死网络、卡住的跳转）会被自动停止——标签页永远不会无限转圈，“日志”中会记录未打开的地址。

**5. 搜索引擎数据独立成模块。** 引擎列表、URL 模板和结果页识别已迁移到 `app/core/engines.py`——不含界面的纯数据：可在任何地方复用，无需 Qt 即可测试。

## 网络磁盘与超大文件夹：彻底告别卡死（v0.7.2）

「日志」的诊断（⏱ 行与「⚠ 界面无响应」）表明：在 WebDAV 磁盘（Z:）上，缩略图和打开文件夹会让整个进程卡住整整一个网络超时（约 60 秒）。从 v0.7.2 起，任何网络操作都不再触及 GUI 线程和 Qt 文件读取：

**1. 图片用 Python I/O 读取、在内存中解码。** `app/core/imgload.py` 先用普通 `open().read()` 读取整个文件——CPython 在读取期间释放 GIL，因此网络卡住的文件只会拖住它自己的工作线程，界面与其他线程照常运行。解码在内存中进行（QImageReader 走 QBuffer，AVIF 走 Pillow）；文件只需遍历一次，而不是按路径读取时的两三次（size() + read() + AVIF 探测）——网络磁盘上的往返请求减少三分之二。

**2. 打开文件夹改为异步。** 文件夹扫描（网络上的 os.scandir）由工作线程执行：点击文件夹或「打开文件夹…」会立即清空列表并显示「正在读取文件夹…」，文件就绪后出现。扫描期间可以切换文件夹——过期结果会被丢弃。启动时自动打开的上次文件夹同样在后台扫描，即使在网络磁盘上启动也瞬间完成。

**3. 文件夹树在后台加载。** 点击与展开节点不再等待 scandir：子文件夹读取完成后出现（在此之前节点仍显示为可展开）。只有需要立即得到结果的地方保留同步读取——文件夹筛选与当前文件夹高亮。

**4. 网络缩略图走独立的窄线程池。** 映射磁盘上的文件（Windows，DRIVE_REMOTE——WebDAV/SMB）通过 2 线程池加载：服务器卡住时只有一两个任务在等待，本地缩略图继续加载。查看原尺寸图同理。

**5. 删除在后台执行。** 回收站与永久删除由工作线程完成（对话框仍在 GUI）：通过网络删除大量文件不再冻结窗口。回收站失败时依旧会如实询问是否永久删除。

**6. 「日志」中的措辞更诚实。** 来自工作线程的慢操作标记为「⏱ 缓慢（后台执行，界面正常）」，而「……这会阻塞界面」只留给真正卡住 GUI 线程的操作——一眼就能从日志看出卡在哪里。

## Google 和 Mail.ru 的复选框重新可用（v0.7.3）

这两个问题都不是「彻底坏了」——而是搜索引擎更改了页面结构，导致复选框注入无法触达卡片：

**1. Mail.ru 合并了搜索门户。** 地址 `go.mail.ru/search_images` 现在重定向到 `mail.ru/search?...&type=images`，而图片结果本身在其内嵌的 `yandex.ru/images` 框架中打开。旧的门槛「仅当主页面本身是结果页时才注入」把 Mail.ru 永远挡在了外面：包装页的地址并不是结果页。现在无论包装页地址如何都会查找结果页框架：只要页面内部存在结果页框架，注入和已选计数就能工作，且搜索引擎列表中的 Mail.ru 直接打开最终地址 `mail.ru/search?text=…&type=images`（少一次重定向）。

**2. Google 再次更改了卡片结构。** Google 的哈希类名每次发布都可能变化，依赖具体类名的选择器迟早会失效。与其赌类名，复选框现在按「质量」上移：如果容器不像卡片、而最佳候选只是缩略图，扫描会向上遍历父节点，取能拿到真实原图的最小外层容器（`/imgres?imgurl=…` 锚点）——但不会上移到吞并相邻卡片的外层。每张卡片一个复选框，「最佳」依旧是原图。

**3. 「日志」中的诊断。** 注入之后日志会写入「图片搜索结果：带复选框的图块：N（框架：M）」；若一个都未识别，则写入「已找到搜索结果页，但未识别出可加复选框的图块……请将此日志发送给开发者」：下一次「复选框不见了」的报告立刻就能回答注入是否到达、识别了多少卡片。

此外，`udm=2` 在任何 Google 国别域名（google.de、google.co.uk 等）上都被视为结果页——Google 会自行在它们之间跳转；复选框扫描按卡片隔离（一张坏卡片不再毁掉整个扫描）。

## 下载后按名称筛选不再被重置（v0.7.5）

场景：在「我的图片」中按名称筛选处于激活状态，从「图片搜索」向同一文件夹保存一批图片——回到标签页时列表已经不带筛选，尽管筛选词仍留在输入框中；只能再按一次 Enter。原因：保存会调用当前文件夹的 `refresh()`，而它按普通扫描重新读取文件夹，忽略了激活的筛选。现在 `refresh()` 的行为与点击目录树相同：筛选激活时会在同一文件夹下重新执行搜索——新文件直接进入同一份结果，无需重新输入。没有筛选词时行为不变——照旧完整重读文件夹。

## 文件重命名——F2、双击文件名与右键菜单项（v0.7.17）

用户需求：“添加重命名文件的功能——既可以通过鼠标菜单，也可以双击文件名”。

现在可以直接在「我的图片」的缩略图条中重命名图片，无需离开程序：右键菜单中的「✏️ 重命名」项、**F2** 键，或双击缩略图下方的**文件名**。编辑框打开时会像资源管理器一样选中不含扩展名的名称——按 Enter 或点击其他位置即应用，按 Esc 取消。双击图片本身仍会在系统查看器中打开。多选时只重命名光标所在的文件，与资源管理器一致。重命名在工作线程中执行（在网络磁盘上窗口不会卡住），缩略图条与已打开图片的状态立即更新。新名称会预先校验：为空、以点或空格结尾，或包含 Windows 禁用字符（`\ / : * ? " < > |`）的名称不会被接受；与现有文件冲突时会恢复旧名称并在状态栏中说明原因。每次结果都会记入「日志」（已重命名/错误及原因）。

## 透明图片的底纹改为可调大小的灰白棋盘格（v0.7.16）

来自工作反馈的愿望：“让透明格式的背景变成用滑块调节大小的灰白方格网格”。

在透明图片（PNG、GIF、WebP、处理结果 “*_nobg.png”…）下方，查看区域现在会绘制经典的棋盘格——白色与灰色方格，就像图形编辑器中的“透明画布”。一眼即可分辨图片哪里透明、哪里画成了白色；此前两者都与深色底面混在一起。方格大小通过工具栏上的滑块调节（旁边的小棋盘图标提示它的作用），选择会在下次启动时记住。仅当图片带 Alpha 通道时才显示棋盘格：JPEG 等不透明格式仍保持原来的深色底面。滚动时方格随图片一起移动（从图片控件原点绘制，如同画布），在高分屏上依然锐利；文字提示（“打开文件夹…”、读取错误）下方不绘制方格。删除背景后选择窗口（v0.7.15）中的预览现在也使用与查看区相同的颜色和方格大小。

测试：`scripts/test_checker.py` —— 瓦片的颜色与几何（对角白/灰、高分屏）、在 QLabel 之上的绘制（透明像素透出方格）、PNG 按 Alpha 开启而 JPEG 关闭、滑块（范围、设置持久化、瓦片重建）、文字下方无方格、选择窗口预览跟随设置的方格大小。

## 删除背景的结果可恢复；模块会在状态栏中汇报自身状态（v0.7.15）

两条来自使用的需求：“处理后可以选择保留文件或恢复原图”，以及“状态栏显示删除背景模块在做什么——模型是否在下载、下载进度等”。

**删除背景后的选择。** 一批处理完成后，程序不再只是把“*_nobg.png”文件留在原图旁，而是在底部弹出询问窗口：“保留结果还是恢复原图？”。窗口内显示第一个结果在棋盘格底上的预览（透明度一目了然）及文件名；若结果不止一个则显示“…等 N 个”。窗口特意做成非模态：打开期间缩略图栏仍可点击，可以逐个放大查看“*_nobg.png”结果。“💾 保留结果”保留文件；“↩ 恢复原图”只删除**本批**结果——原图从未被改动，因此恢复是安全的（结果是程序几秒前刚生成的，删除时绕过回收站，不会弄乱它）。用叉号或 Esc 关闭同样算“保留”：只有明确点击才会丢弃结果。若未回答旧问题就启动新一批，旧问题按“保留”关闭。每次选择都会写入日志（保留/恢复/逐文件错误），恢复后缩略图栏立即刷新。

**状态栏汇报模块状态。** 以前模型由 pooch 下载，而它的进度显示在控制台里——程序没有控制台，用户只能默默等待 5–176 MB 下载完成（pythonw 版本的 tqdm 甚至会崩溃，直到 v0.7.14 打了补丁）。现在程序接管下载：模型由应用本身通过 requests 下载，状态栏展示模块的完整历程——“正在准备模型 u2netp…” → “正在下载模型 u2netp：1.2 MB / 4.7 MB（26 %）” → “模型 u2netp 下载完成（4.7 MB）” → “模型 u2netp 已就绪” → “删除背景：2/5 — cat.jpg…”。下载完的文件仍由 pooch 校验（哈希）；网络中断时未完成的“.part”会被清理并由 pooch 重试——进度提示变少，但模型最终会到手。下载结果（大小、耗时）写入日志；百分比刷新只出现在状态栏，不会刷屏日志。

测试：`scripts/test_rembg.py` — 134 项检查，包括真实 rembg 的端到端运行（空模型缓存 → 下载信号 → 结果文件 → 选择）、断网场景的流式下载单元测试、pooch 包装器与恢复原图流程。

## 删除背景在无控制台下也能工作；启动在网盘上不再卡顿（v0.7.14）

修复了两个现场反馈：「🪄 无法删除背景 — 'NoneType' object has no attribute 'write'」（删除背景完全无法工作）和启动时的「⚠ 界面无响应 ≈1742 毫秒」。

**Windows 无控制台下的删除背景。** 程序通过 pythonw 运行——没有控制台，Python 的 `sys.stdout`/`sys.stderr` 为 `None`。rembg 模型下载经过 pooch 和 tqdm 进度条，而 tqdm 写入 `sys.stderr` 并崩溃：“'NoneType' object has no attribute 'write'”：模型从未保存成功，每次尝试都重复同一错误（第一次在缓慢的 GitHub 连接上耗了一分钟，第二次立即失败）。现在处理前会安装写入黑洞的占位流（`_ensure_stdio`）；真正的控制台不受影响，调用幂等。

**磁盘树改为后台读取。** 磁盘列表原先在 GUI 线程里用 `QStorageInfo` 构建：对尚未连接的网络盘的第一个请求会建立 SMB 会话——窗口卡住几秒（正是「≈1742 毫秒」反馈）。现在卷的枚举交给工作线程（_DrivesTask）：树立即显示，磁盘区块在列表就绪后补齐；重建时（切换语言、⟳）磁盘从缓存瞬时恢复。如果磁盘集合未变，区块完全不重建（展开的分支保持展开），只刷新容量提示。重建后当前文件夹的定位改为异步行走（v0.7.6 原则），同步定位也能重读后台加载尚未落地的节点（用令牌取消迟到结果）。

测试：`scripts/test_rembg.py` — 63 项检查，包含精确场景（空模型缓存、stdio = None → 模型下载成功、结果文件生成）；test_tree — 磁盘从缓存瞬时恢复、后台枚举、隐藏虚拟卷；test_folder_search — 等待方式改为适配异步树。

## 当前任务显示在底部状态栏（v0.7.13）

日志收集了全部工作记录，但还得先打开那个标签页。现在每条日志行（事件、警告、错误）都会同步显示到窗口底部状态栏的左侧：无论程序在做什么——搜索、下载、删除背景、安装或卸载 rembg 模块、同步磁盘树——当前任务无需切换标签页即可看到。

来自工作线程的事件（搜索、下载、缩略图）通过 Qt 信号队列送达状态栏——文字随工作节奏更新，界面不会卡住。显示规则很简单：不显示 DEBUG（技术噪音），多行记录（如错误跟踪）只显示第一行，过长的行截断到 220 个字符。消息会一直保留，直到被下一个事件替换：程序“播报”自己正在忙什么，不会在漫长的模块安装进行到五秒时就消失。

状态栏的其他元素（右侧「我的图片」状态、语言选择和更新按钮）未受影响。测试：`scripts/test_status_log.py` — 12 项检查，包括来自工作线程的事件以及启动时「就绪」提示不被覆盖。

## 在程序内直接删除背景：rembg 模块（v0.7.12）

来自电商网站和搜索结果的图片常常需要去掉背景。Image Hunter 现已集成 **rembg**（github.com/danielgatis/rembg）——目前最活跃的开源背景删除项目：MIT 许可，全部通过 ONNX Runtime 本地完成，无需云端和密钥。

**无需终端即可安装。** 「我的图片」工具栏上的「🪄 删除背景」按钮和缩略图右键菜单中的同名项：如果模块尚未安装，程序会自动提议通过 pip 安装 `rembg[cpu]`（隐藏窗口，与 v0.7.6 的更新器同一手法），随后**立即继续**对点击的那张图片删除背景。右键菜单中还有「安装删除背景模块…」入口。

**卸载模块——同样在程序内。** 同一菜单中的「卸载 rembg 模块和模型…」：pip 删除包和 ONNX Runtime，然后清空已下载模型的缓存（`~/.rembg`，旧版本为 `~/.u2net`）；删除前程序会显示将释放多少空间。磁盘上不会残留任何内容。

**工作方式。** 结果以 `名称_nobg.png` 保存到原图旁边，并立即出现在缩略图栏；重复处理结果会被拦截（“这已经是无背景图片”）。支持多选——一次处理多张。处理在后台线程进行（整批共用一个 rembg 会话——模型只加载一次内存）；网络磁盘上的文件由窄线程池读取，界面不会卡住。进度显示在状态栏，逐文件结果和错误记入日志。模型选择在「模型」子菜单：`u2netp`（约 5 MB，快速，默认）、`u2net`（约 176 MB）、`isnet-general-use`（约 170 MB，边缘最干净）；模型在首次使用时自动下载，并跨会话记忆。

测试：`scripts/test_rembg.py` — 60 项检查，包含真实 rembg 的端到端运行（pip 安装 → 下载模型 → 生成结果文件 → 清理缓存）。

## 稳定性与速度：全代码审计结果（v0.7.11）

对全部代码重新审查，排查卡顿、竞态和慢点。共发现并修复八处薄弱环节：

**1. GIF 不再在界面线程中读取。** 自 v0.7.2 起完整图片已在后台解码，但 GIF 是例外：`QMovie` 直接在 GUI 线程打开文件，在网络磁盘失灵时，连读取文件头都会把窗口冻结到网络超时。现在 GIF 文件在工作线程中读取（同样是会释放 GIL 的 Python I/O），动画基于内存中的 `QBuffer` 构建——GUI 线程中最后一处文件读取已消除。

**2. 并行下载不再互相覆盖。** 文件名取自链接，六个并行下载经常会重名（`image.jpg`）：经典的“是否存在 → 创建”检查看不到竞态，一个文件会静默覆盖另一个。现在文件由操作系统原子化创建（`O_CREAT|O_EXCL`）：落败的线程会诚实取得下一个空闲编号（`image-1.jpg`、`image-2.jpg`…），不再丢失任何文件。

**3. 连接复用。** 每个请求都新建 TCP/TLS 连接：来自同一 CDN 的一百张图片的批量任务要为每张支付一次握手。现在每个工作线程拥有自己的 `requests` 会话——连接被复用，批量下载明显更快，套接字也不再堆积在 `TIME_WAIT`。失败的响应立即关闭，而不再等垃圾回收器。

**4. “打开文件夹…”的高亮不再卡顿。** 通过对话框选择文件夹会在目录树中同步高亮：在网络磁盘上，路径的每一层都要在 GUI 线程中支付一次扫描。现在高亮采用异步行走（自 v0.7.6 起程序启动时使用的同一机制）——保存一批图片到新文件夹时同样如此。

**5. 放大查看大图时调整窗口大小不再卡顿。** 拖动窗口边缘会在每个像素上都重新按窗口缩放图片，而大图的平滑缩放需要几十毫秒——延迟叠加成明显的卡顿。现在只在窗口停止变化后重新计算一次。

**6. “更新”不再重复。** 双击更新按钮会启动两次网络检查并连续弹出两个对话框。检查进行中时，重复点击不再执行任何操作。

**7. 回收站查询每个磁盘只做一次。** 删除前程序会确认磁盘是否有回收站；选中一百个文件时，每个文件都会向 shell 发起一次查询。结果现在按磁盘根缓存。

**8. 删除报告变得诚实。** 在没有回收站的磁盘上执行“永久删除”时，状态与日志中却计为“已移入回收站”：计数依据的是删除阶段编号，而非实际模式。现在“永久删除：N”与日志事件 `delete_perm` 的记录都是真实的。

**9. 既有网络缓存机制运行正常**（v0.7.2–v0.7.10）：磁盘的网络属性、回收站存在性、懒加载缩略图、后台扫描与分批搜索——审计确认这些机制均按设计工作。

## 文件夹筛选在选中的文件夹或磁盘内搜索（v0.7.10）

**1. 搜索范围 = 焦点。** 以前在“🔍 筛选文件夹…”中输入字母会同时遍历树的所有分支——主目录、收藏夹和所有磁盘，包括网络磁盘：在 WebDAV/SMB 上搜索会拖长数秒，结果中还会闪现其他磁盘里的“无关”文件夹。现在搜索深入树中当前选中的内容：选中 Z: 磁盘——筛选会搜索整个该磁盘；选中“Автозапчасти”文件夹——只搜索其子文件夹。其他分支整体隐藏且完全不会被遍历——这正是网络磁盘上省时的关键。若未选中任何内容，则像以前一样搜索所有磁盘。树上方的计数器会显示搜索位置：“已找到文件夹：2（在“Z:/Автозапчасти”内）”。

**2. 更改焦点即更改范围。** 筛选激活时点击另一文件夹或磁盘，筛选会立即按新范围重新应用（以前文本不变时筛选不会重新运行）。回车只打开范围内的匹配项——不会把您带到别的磁盘。

## 收藏夹文件夹 — 始终位于目录树顶部（v0.7.9）

**1. 两种方式将文件夹加入收藏夹。** 目录树顶部的“☆”按钮可将当前打开的文件夹加入收藏夹（“★”则移除）；右键点击“磁盘与文件夹”树中的任何文件夹，选择“⭐ 加入收藏夹”/“从收藏夹移除” — 适用于当前打开路径够不着的深层文件夹。加入和移除都会写入“日志”。

**2. 收藏夹位于目录树顶部。** 带金星标的收藏夹文件夹在每次启动时都排在目录树最前面 — 在“主目录”和磁盘列表之前；列表保存在设置中。除此之外它们与普通文件夹一样：懒展开、单击打开、文件夹筛选同样能找到它们。从收藏夹移除不会动文件夹本身。

## 日志标明事件属于哪个搜索引擎（v0.7.8）

**1. 日志行带有搜索引擎名称。** “全局搜索”会为每个搜索引擎打开一个标签页，而以前从日志中无法判断是谁：连续八条“已找到搜索结果页,但未识别出可加复选框的图块……”意味着八个不同的搜索引擎，却不知道是哪一个更改了页面结构。现在所有标签页事件都带有方括号中的搜索引擎简称：“[Startpage] 页面在 45 秒内未加载完成……”、“[Google] 图片搜索结果:带复选框的图块:2……”、“[Mail.ru] 保存错误……”、“[Yandex] 保存完成:成功 3 个……”、“[Google] 已收集链接……”——渲染进程崩溃也带有标记。提交问题时只需附上日志：立刻就能看清是哪个搜索引擎出了什么问题。

## 搜索状态移至底部状态栏（v0.7.7）

**1. 搜索信息显示在状态栏中。** 以前按名称搜索的结果（“搜索“96985730”：0 个文件”）绘制在搜索框所在的顶部工具栏中：较长的文字会撑大工具栏，查看结果时视线还得在窗口里来回移动。现在该状态显示在窗口底部的状态栏中 — 与服务消息和语言切换同处一行：文字位于语言选择框和更新按钮的左侧。“我的图片”的其他状态也一并移了过去 — “正在读取文件夹…”、“已复制 N”、“已删除 N”、当前图片的信息；顶部工具栏只保留按钮、搜索框和“忽略连字符”。

## 无终端窗口的更新，以及显示当前位置的目录树（v0.7.6）

**1. 应用内更新 — 零终端窗口。** 以前安装程序在可见的控制台窗口中运行（v0.7.4 之前甚至有两三个），更新后窗口仍留在屏幕上。现在 cmd 以 CREATE_NO_WINDOW 标志启动：更新期间和更新后都不会出现终端。安装程序输出写入日志 `%TEMP%\ImageHunter_update.log`；失败时显示普通对话框（含错误信息和日志路径），而不是控制台。此外，安装路径不再写入批处理文件，而是通过环境变量传递 — 即使安装目录或用户名包含非 ASCII 字符，更新也不会出错。应用会提前说明预期：确认更新后会弹出提示 — 更新将在后台进行，应用会关闭并在 1–2 分钟后自动重新启动。

**2. 目录树自动展开到当前文件夹。** 如果启动时恢复了上次文件夹和名称筛选，以前看不出显示的图片位于何处 — 目录树保持折叠。原因：树的选中状态绑定在后台文件夹扫描的结果上，而恢复的搜索赶在扫描之前并连同选中状态一起丢弃了扫描结果。现在目录树立即开始异步地逐级展开到当前文件夹（在网络磁盘上不会卡死界面）；如果文件夹不可达，则高亮最近的现有节点；手动选择和通过对话框打开会覆盖自动展开，而不是相反。

## 功能

**📁 我的图片** — 本地看图：
- **左侧磁盘和文件夹树**：挂载的磁盘和设备（悬停提示显示剩余空间）、收藏夹文件夹 ⭐ — 始终位于顶部、
  “主目录”和“图片”快捷链接；文件夹懒展开，点击文件夹立即显示其中图片；面板宽度可用鼠标调整；
  “⟳”按钮刷新磁盘列表（插入 U 盘后使用）；
- **文件夹筛选**：树上方的“🔍 筛选文件夹…”框 — 输入时树中只保留名称包含这些字母的文件夹：其余隐藏，
  到匹配项的分支自动展开，树上方的计数器显示找到的文件夹数量及搜索位置；搜索深入到树中当前选中的
  文件夹或磁盘内（选中什么就搜索什么；未选中时搜索所有磁盘）；筛选即时完成，不会重新扫描磁盘 —
  树只在预算内加载更多层级（每次 300 个文件夹或 1.5 秒），再大或网络的磁盘也不会卡住窗口；
  不区分大小写，单击打开文件夹，回车打开第一个结果，Esc 重置；不显示隐藏文件夹；
- **懒加载缩略图**（见上文网络部分）及“🖼 缩略图”开关；
- **多选与拖放**：在缩略图条中选中图片（Ctrl/Shift，与资源管理器相同）后拖到资源管理器、邮件或任何其他应用 — 传递的是原始文件（`text/uri-list`）；拖放启动有三条独立保障（事件过滤器、自实现的鼠标移动跟踪、Qt 内置机制），每一步都会写入日志；**如果无法拖动 — 无拖放备用方案：** `Ctrl+C`（或右键 →“复制所选文件”），然后在需要的地方粘贴 — 资源管理器或浏览器中 `Ctrl+V`；
- **按文件名搜索**：输入文件名的一部分 — 找到当前文件夹及所有子文件夹中的图片；无需通配符，不区分大小写，结果随扫描逐步出现；**“忽略连字符”** 复选框在匹配时不区分连字符 — 查询“23542-23523”同样能找到“2354223523”（零件编号的写法不一致：连字符位置不同或没有）；复选框状态会被记住；
- **删除文件**：按 `Delete` 或右键 →“🗑 删除” — 所选图片移入回收站（可从资源管理器还原）；确认对话框显示文件数量，每次失败都会连同原因写入日志。在没有回收站的磁盘上（网络磁盘、部分移动设备），程序会在单独确认后提供永久删除；
- 启动时自动打开上次的文件夹（不超过 2000 张图片时），并恢复关闭前的最后一个搜索请求；
- 全屏查看，缩放（`+` / `−` / `Ctrl+滚轮`）、“适应窗口”、“100%”；
- ←/→ 导航，自然排序（file2 < file10）；
- **支持 AVIF**：`.avif` 文件在缩略图条中显示并支持全屏查看，链接下载的 AVIF 图片（电商平台即使以 `.jpg` 名义也返回 AVIF）可重新保存为任一格式；解码器为 Pillow + pillow-avif-plugin（自动安装）；
- 选中的图片在后台线程加载 — 在网络磁盘上选择文件（或读取大型 AVIF）不再卡住窗口（“未响应”）；
- 动图 GIF，支持 JPG/PNG/WEBP/BMP/GIF/AVIF；
- 双击缩略图 — 用系统看图程序打开；“在文件管理器中显示”按钮；
- 缩略图条可通过分隔条用鼠标拉伸（面板宽度在多次运行之间保留），搜索框位于工具栏。

**🌐 图片搜索** — 内置 Chromium 浏览器：
- **浏览器式多标签页**：“＋”/Ctrl+T 新建搜索标签页，每个标签页有独立的搜索引擎和浏览器；右键标签页可复制 / 关闭 / 关闭其他 / 关闭右侧；× 关闭标签页（关闭最后一个会新建空白页），标签页可拖动排序；标签页标题为所选搜索引擎，圆点为品牌色（Yandex — 红色，DuckDuckGo — 橙色，Google — 蓝色，Bing — 绿色）；打开的标签页在下次启动时恢复；
- **一个输入框，全部搜索引擎**：标签页上方有共享搜索框；回车或点击**“🔎 全局搜索”**，
  关键词立即在全部 11 个搜索引擎中打开 — 每个引擎一个标签页（已打开的标签页会重新加载结果）；
- 搜索引擎（11 个）：Yandex 图片、Google、Bing、DuckDuckGo（安全模式）、
  Brave、Startpage、Mojeek、Baidu、Sogou、Naver、Mail.ru；

- **结果卡片上的复选框**：用橙色勾选标记需要的图片 — 按钮上出现计数，“下载已选”将下载大尺寸原图（Yandex 取 `origUrl` — 与点击预览打开的是同一个文件，例如 `avatars.mds.yandex.net/get-mpic/…/orig`；其他搜索引擎取卡片链接参数中的原图）；

- 复选框同样支持最新版 Google 图片结果页（udm=2）：识别无扩展名的 `encrypted-tbn0.gstatic.com`/`googleusercontent` 缩略图，稍后加载图片的懒加载卡片也会出现勾选，页面的持续重绘不再延迟复选框的出现；

- “日志”中可见复选框诊断：结果页上已安装复选框的图块数量（或“一个都未识别” —— 请将日志发送给开发者）；
- 无限滚动加载的卡片也会被复选框覆盖；
- **“✕ 取消选择”** — 一键取消所有橙色勾选（有勾选时才可用）；
- **“💾 保存到文件夹”** — 勾选的卡片转换为所选格式（WebP、PNG、JPEG、BMP、TIFF — 选择器在按钮旁且会被记住），保存到“我的图片”标签页当前打开的文件夹：第一个文件为 `名称.ext`，之后为 `名称-1.ext`、`名称-2.ext`… **绝不覆盖已有文件：** 跳过被占用的名称，且写入前会再次检查 — 如果 `name.webp` 和 `name-2.webp` 已存在，新文件将变为 `name-1.webp` 和 `name-3.webp`。JPEG/BMP 的透明部分铺白底，尊重 EXIF 旋转。保存时会询问名称（默认为搜索关键词）；若未打开文件夹，会提示选择；保存的文件立即出现在看图中。
- **“📋 收集链接”** — 与之前相同：将打开的结果页上的所有图片（缩略图、DuckDuckGo 代理中的原图、Yandex `data-bem`/`data-state` JSON 中的原图）整批送到下载。

**⬇️ 下载** — 保存管理器：
- 按直链批量下载（最多 6 个文件并行）；
- 手动粘贴链接（每行一个）；
- 会话内链接去重，不覆盖已有文件（`-1`、`-2`… 后缀）；
- 文件名取自 URL，扩展名按 `Content-Type` 修正；
- 当 CDN 拒绝访问（401/403/429）时，下载器会尝试备用方案：不带 Referer、带图片站点自身的 Referer，对 Cloudflare `/cdn-cgi/image/…` 包装链接则尝试直连原始图片地址；
- 下载文件夹可选（默认 `Pictures\ImageHunter`），单文件上限 100 MB。

**📜 日志** — 运行记录（标签页添加在最右侧）：
- 打开了哪些文件夹、搜索找到了什么、哪些文件被拖动及拖放如何结束、下载/保存了多少、发生了哪些错误；如果某个文件下载或保存失败，日志中会同时显示链接和原因（例如“不是图片 (text/html)”、超时、“文件过大”）；
- 错误标红、警告标橙；日志保留最近 5000 行；
- “🧹 清空”与“📋 复制全部”按钮 — 便于将日志附在错误报告中；未捕获的异常同样进入日志；
- 主窗口标签页可用鼠标拖动并任意重排。

应用图标（“带放大镜的照片”）由程序绘制并嵌入窗口；随附 Windows 多尺寸 `app_icon.ico`。

## 安装

### 一行命令安装（推荐）

安装程序会询问安装文件夹，创建虚拟环境，下载依赖并创建快捷方式。

**Windows**（PowerShell — 整行复制）：

```powershell
irm https://codeload.github.com/teliy/image-hunter/zip/refs/heads/main -OutFile "$env:TEMP\ih.zip"; Expand-Archive "$env:TEMP\ih.zip" "$env:TEMP\ih-src" -Force; powershell -NoProfile -ExecutionPolicy Bypass -File "$env:TEMP\ih-src\image-hunter-main\install.ps1"
```

**Linux**（bash）：

```bash
curl -fsSL https://raw.githubusercontent.com/teliy/image-hunter/main/install.sh | bash
```

安装程序检查 Python 3.10–3.14（缺失时提议安装），询问安装位置，下载代码（无需 git），创建 `.venv`，安装依赖，并创建开始菜单快捷方式（Windows）或 `.desktop` 条目与 `image-hunter` 命令（Linux）。

> **Alpine Linux (musl)：** 安装程序支持 `apk` 并接受 Python 3.10–3.14（stable 为 3.12，edge 为 3.14）。PySide6 没有 musl 轮子，因此安装程序会安装 `gcompat` 并允许 pip 选用 glibc 轮子——通常足够，但 QtWebEngine 在 musl 上仍可能无法启动；更稳妥的方案是使用 Docker 或基于 glibc 的发行版（Debian、Ubuntu、Fedora）。

**更新与卸载：**

| 操作 | Windows | Linux |
|---|---|---|
| 更新 | `ImageHunter.bat update`，或直接在程序内：“帮助 → 检查更新” / “🔄 更新”按钮 (Ctrl+U) | `image-hunter update` |
| 卸载 | `ImageHunter.bat uninstall` | `image-hunter uninstall` |
| 版本 | `ImageHunter.bat version` | `image-hunter --version` |

### 从私有仓库安装（使用令牌）

对于**私有**仓库，GitHub 不会在未授权的情况下通过 `raw.githubusercontent.com` 提供文件 — 常规单行命令会返回 `404: Not Found`。需携带 `Authorization` 头下载安装程序并在本地运行。

**Windows**（PowerShell，一行 — 替换为你的令牌）：

```powershell
$t="ghp_YOUR_TOKEN"; iwr https://raw.githubusercontent.com/teliy/image-hunter/main/install.ps1 -Headers @{Authorization="token $t"} -UseBasicParsing -OutFile "$env:TEMP\ih-install.ps1"; $env:IH_GH_TOKEN=$t; powershell -NoProfile -ExecutionPolicy Bypass -File "$env:TEMP\ih-install.ps1"
```

**Linux**（bash）：

```bash
export IH_GH_TOKEN=ghp_YOUR_TOKEN
curl -fsSL -H "Authorization: token $IH_GH_TOKEN" https://raw.githubusercontent.com/teliy/image-hunter/main/install.sh | bash
```

令牌需要仓库读取权限：classic — `repo` scope；fine-grained — “Contents: Read-only”。安装程序将令牌保存在安装文件夹内的 `.gh_token` 中以便日后自动更新；不需要时请删除该文件。
非交互运行变量：`IH_ASSUME_YES=1`、`IH_DIR=<路径>`、`IH_PYTHON=/path/to/python`（自动探测不合意时手动指定解释器）。

## 链接收集的原理

JS 脚本（`app/core/extractor.py`）在结果页上运行，收集 `img[src]`、`srcset`、懒加载 data 属性；从 `external-content.duckduckgo.com/iu/?u=…` 代理中还原原图；解析 Yandex `data-bem` 属性中的 JSON；扫描原始 HTML（还原 `\u002F` 和 `\/`）寻找文件直链。每次最多收集 500 个链接。页面并未被“破解” — 只利用浏览器已经下载并显示的内容。

## 故障排除

**程序在 Linux 上卡死（Wayland 会话）。** 当 wayland 插件加载失败时（启动时终端
显示 `Could not load the Qt platform plugin "wayland"`），应用程序会通过 XWayland
运行，此时内置浏览器与显卡驱动的组合可能会导致整个窗口彻底卡死。从 v0.6.4 起
Image Hunter 会在启动时自动检测这种情况并禁用内置浏览器的 GPU —— 页面改用软件
渲染（不影响搜索和下载速度），并在“日志”中写入说明。手动控制：

- `IH_GPU=0 image-hunter` —— 强制禁用 GPU；
- `IH_GPU=1 image-hunter` —— 保持 GPU 启用，忽略自动检测；
- `QTWEBENGINE_CHROMIUM_FLAGS="--disable-gpu" image-hunter` —— 通过 Chromium 标准
  标志达到同样效果（多个标志用空格分隔）。

如果搜索标签页始终空白（Alpine/musl 以及 Chromium 沙箱无法启动的其他系统），
请添加 `--no-sandbox`：

    QTWEBENGINE_CHROMIUM_FLAGS="--no-sandbox --disable-gpu" image-hunter

**搜索标签页灰色，终端出现 render process 相关信息** —— 程序现在会自动重启崩溃
的标签页渲染进程（最多两次），事件会显示在“日志”中。

**页面永远“加载中”，标签页无响应** —— 从 v0.7.0 起加载会在 45 秒后自动停止，
“日志”中会记录该地址。如果所有网站都如此，请检查网络/代理。

**“日志”中出现 sandbox 相关记录** —— 您的 Linux 内核禁止用户命名空间；没有它
Chromium 沙箱无法启动，标签页会循环崩溃（看起来像卡死）。程序已自动在无沙箱模式
下启动浏览器。恢复沙箱：`IH_NO_SANDBOX=0 image-hunter`。

**终端出现 `handshake failed … net_error -202` 之类的错误** —— 这不是程序卡死，
而是不信任网站证书：请检查系统时间是否正确、是否有拦截 HTTPS 的杀毒软件/代理，
以及系统根证书（`ca-certificates`)是否齐全。出现 `net_error -100`（连接被关闭）
时请检查网络可用性。

**卡死的是旧版本** —— 如果终端显示 `js: Uncaught TypeError … appendChild`，说明
您的版本低于 v0.6.4：请更新（Windows 用 `ImageHunter.bat update`，Linux 用
`image-hunter update`）。
